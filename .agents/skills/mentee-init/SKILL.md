---
name: mentee-init
description: 이 저장소에서 멘티에게 간단한 질문을 하고 이름, Git 작성자와 GitHub 게시 설정을 자동으로 구성할 때 사용한다.
---

학생에게 터미널 명령 실행을 요구하지 않습니다. 저장소 루트에서 `config/mentees.json`을 읽습니다. 먼저 기존 `.mentee/profile.json`과 Git 작성자 이메일을 확인해 이미 있는 값은 다시 묻지 않습니다. 필요한 값은 일반 대화에서 한 번에 묻습니다: "이름(염동권/김세은/김선경)과 GitHub 커밋 이메일을 알려주세요. 이름을 선택해 입력창에 채웠다면 **전송 버튼 또는 Enter**를 눌러야 답변이 전달됩니다." 학생이 이름만 보냈다면 즉시 이메일만 묻고, 이메일만 보냈다면 이름만 묻습니다. 두 값이 모두 모이기 전에는 설정 완료라고 말하지 않습니다.

Codex에서 선택형 항목을 누르면 텍스트가 입력창에 들어갈 수 있지만, 그 자체가 메시지 전송이나 에이전트 실행은 아닙니다. 비동기 질문 도구의 `accepted` 응답도 학생의 답변이 아닙니다. 초기 설정에는 비동기 선택형 질문을 사용하지 말고 위의 일반 대화 질문을 사용합니다. 답변 없이 스킬을 다시 호출하면 현재 설정 상태를 확인하고 아직 필요한 값만 다시 묻습니다. 이름·이메일을 추정해 채우지 않습니다.

로컬 `.env`에 토큰이 없으면 이 저장소에 `Contents: Read and write` 권한을 가진 본인 계정의 fine-grained PAT를 지금 등록할지 선택하도록 안내합니다. 학생이 토큰을 대화에 입력하는 것은 허용되지만, 대화 기록에 남는다는 점은 알려줍니다. 토큰이 아직 없어도 이름·이메일을 받으면 초기 설정을 완료하고 `/commit-push` 또는 `$commit-push`를 처음 사용할 때 다시 받습니다. 토큰 값을 답변이나 로그에 되풀이하지 않습니다.

받은 값을 JSON으로 `python3 scripts/mentee_setup.py --json-stdin`의 표준 입력에 전달해 에이전트가 직접 실행합니다. `name`, `email`, `github_token`(있을 때만)을 사용합니다. 토큰은 명령줄 인자나 Git 원격 URL에 넣지 않고, 사용자 입력을 셸 명령에 삽입할 때는 리터럴 heredoc 또는 동등한 안전한 stdin 전달 방식을 사용합니다. 스크립트가 `.mentee/profile.json`과 로컬 `.env`를 만들고 Git 푸시 전 비밀값 검사를 활성화합니다.

설정 후 프로필의 이름·담당 초점·첫 작업 ID와 Git 작성자 설정만 확인합니다. `.env` 값은 출력하지 않습니다. **설정 완료에서 멈추지 않습니다.** `docs/MENTEE_PLAYBOOK.md`와 `docs/WORKBOARD.md`를 읽고 실제 파일 상태를 확인한 다음, 첫 작업 ID를 출발점으로 추천 작업 하나와 흥미에 따른 대안 1~2개를 제시합니다. 각 선택지에는 왜 필요한지, 바로 확인할 데이터/코드, 작은 완료 산출물을 붙입니다. 학생이 선택하면 그 자리에서 첫 탐색을 함께 시작합니다. 작업을 원격 저장소에 반영할 때는 `commit-push` 스킬을 사용한다고 알려줍니다.
