name: mentee-init
description: 이 저장소에서 멘티에게 간단한 질문을 하고 이름, Git 작성자와 GitHub 게시 설정을 자동으로 구성할 때 사용한다.
---

학생에게 터미널 명령 실행을 요구하지 않습니다. 저장소 루트에서 `config/mentees.json`을 읽고 `.mentee/profile.json`과 Git 작성자 설정을 확인합니다. **일반 대화의 선택지나 입력창 자동 완성으로 묻지 말고, 사용 가능한 ask UI 도구를 호출합니다.** Codex에서는 `request_user_input_async`(동기식 `request_user_input`이 제공되면 그것도 가능)를 사용합니다. Claude Code에서는 제공되는 ask UI 도구를 사용합니다. 해당 도구가 실제로 없을 때만 대화로 질문합니다.

질문은 아래 순서로 **ask 필드에서 하나씩** 처리합니다. 이미 설정된 프로필의 값은 재사용해 해당 질문을 건너뛸 수 있지만, 다른 멘티로 바꾸면 이름과 이메일을 다시 받습니다.

1. 이름이 없으면 선택형 ask 질문을 보냅니다. Codex 예: `request_user_input_async({"questions":[{"title":"멘티 이름을 선택해 주세요.","options":["염동권","김세은","김선경"]}]})`. 실제로 제출된 답변에서 이름을 확인합니다.
2. 이름 답변이 도착한 **다음에** 이메일용 ask 질문을 보냅니다. Codex 예: `request_user_input_async({"questions":[{"title":"GitHub 커밋 이메일을 입력해 주세요."}]})`. 옵션 없는 질문의 자유 입력 필드에서 이메일을 받습니다. 이메일 형식이 잘못되면 같은 ask 필드에서 다시 묻습니다. 이름 선택 뒤에 일반 대화 입력창으로 이메일을 요구하지 않습니다.
3. 토큰이 없으면 ask UI로 "GitHub 토큰을 지금 등록할까요?"를 선택하게 합니다. 나중에 등록을 고르면 토큰 없이 설정을 완료합니다. 지금 등록을 고르면 자유 입력 ask 필드로 토큰을 받습니다.

비동기 질문 도구의 `accepted`는 질문 표시가 접수되었다는 뜻일 뿐 답변이 아닙니다. 사용자가 ask UI를 제출해 실제 답변이 새 메시지로 도착할 때까지 그 값에 의존하는 단계를 진행하지 않습니다. 답변을 받은 다음 턴에는 **같은 초기 설정을 이어서** 다음 ask 질문이나 설정 스크립트를 실행합니다. 답변 없이 스킬을 다시 호출하면 현재 설정 상태를 확인하고 필요한 ask 질문만 다시 제시합니다. 이름·이메일을 추정해 채우지 않습니다.

등록할 토큰은 이 저장소에 `Contents: Read and write` 권한을 가진 본인 계정의 fine-grained PAT여야 합니다. ask 필드에 입력한 토큰도 대화 기록에 남을 수 있음을 알립니다. 토큰이 없어도 이름·이메일을 받으면 초기 설정을 완료하고 `/commit-push` 또는 `$commit-push`를 처음 사용할 때 다시 받습니다. 토큰 값을 답변이나 로그에 되풀이하지 않습니다.

받은 값을 JSON으로 `python3 scripts/mentee_setup.py --json-stdin`의 표준 입력에 전달해 에이전트가 직접 실행합니다. `name`, `email`, `github_token`(있을 때만)을 사용합니다. 토큰은 명령줄 인자나 Git 원격 URL에 넣지 않고, 사용자 입력을 셸 명령에 삽입할 때는 리터럴 heredoc 또는 동등한 안전한 stdin 전달 방식을 사용합니다. 스크립트가 `.mentee/profile.json`과 로컬 `.env`를 만들고 Git 푸시 전 비밀값 검사를 활성화합니다.

설정 후 프로필의 이름·담당 초점·첫 작업 ID와 Git 작성자 설정만 확인합니다. `.env` 값은 출력하지 않습니다. **설정 완료에서 멈추지 않습니다.** 개발 시작 전에 `pull` 스킬로 원격 `main`의 새 커밋을 확인하고, `docs/MENTEE_PLAYBOOK.md`와 `docs/WORKBOARD.md`를 읽어 실제 파일 상태를 확인합니다. 첫 작업 ID를 출발점으로 추천 작업 하나와 흥미에 따른 대안 1~2개를 제시합니다. 각 선택지에는 왜 필요한지, 바로 확인할 데이터/코드, 작은 완료 산출물을 붙입니다. 학생이 선택하면 그 자리에서 첫 탐색을 함께 시작합니다. 작업을 원격 저장소에 반영할 때는 `commit-push` 스킬을 사용한다고 알려줍니다.
