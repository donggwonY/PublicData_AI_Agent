# A-03 추가 질문 평가 준비 — 2026-11-03

상태: 정답 근거 준비 및 사용자 제공 실제 응답 4문항 평가 기록 완료. 아래 실행 절차는 계획이며 실제 확인 범위는 결과 절을 따른다.

기존 카페 출구/주소 비교·지도 평가를 반복하지 않고 지역 비교, 자리 이력, 생존 통계, 모호한 주소를 추가한다. [로컬 도구 결과](service_extended_reference_20261103.json)는 APP_DATA_SOURCE=parquet, 기준일 2026-10-13의 참고 출력이다. 공개 DB·모델 응답 검증 또는 독립 통계 재계산이 아니다. 공개 도구의 버전·인자·결과가 다르면 차이 원인을 먼저 확인한다.

| ID | 사용자에게 보낼 질문 | 필수 확인 기준 |
| --- | --- | --- |
| E1 지역 비교 | 수성구와 중구의 카페 3년 생존율을 비교해 줘. 이 수치만 보고 수성구에 창업하는 게 더 유리하다고 볼 수 있어? | 같은 코호트·업종 정의, 수성구 n=2057/61.8%, 중구 n=1616/59.0%. 지역 통계를 개인 성공 확률이나 인과 효과로 단정하지 않음 |
| E2 자리 이력 | 대구 중구 동성로5길 83 1층에는 어떤 업종들이 있었어? 한 가게가 계속 바뀐 자리야? | 총 6기록, 종료 3/기준일 영업 표시 3, 최대 동시 3. 다점포 층을 단일 가게의 연속 교체 이력으로 단정하지 않음. 현재 실제 영업 상태는 미확인 |
| E3 생존·예측 구분 | 수성구 카페의 1년·3년·5년 생존율과 중앙생존기간을 알려줘. 내가 새로 열 카페도 그 확률로 살아남는다는 뜻이야? | n=2057, 86.3/61.8/45.7%, 중앙 4.3년. 2010년 이후 인허가·Kaplan–Meier·기준일 중도절단 설명. A-02 개별 예측 모델과 구분 |

각 질문은 새 대화에서 1회씩 실행한다. 정답 숫자·이 문서를 모델에 주지 않는다. 모호한 주소 질문은 되묻기까지를 평가하며 후속 주소 선택은 별도 기록한다. E1과 E3의 지표가 겹치지만 지역 비교와 개인 예측의 구별을 각각 평가한다.

실행별 기록: 입력 질문, 화면 모델, 표시 데이터 출처·기준일, 호출 도구·인자·펼친 결과, 최종 답변, 가능하면 입력부터 응답 종료까지 걸린 시간. 측정하지 못한 시간·버전은 미확인으로 표시하고 도구 로컬 실행시간으로 대체하지 않는다. 사용자 스크린샷과 에이전트 직접 실행을 구별한다.

판정은 수치 일치/도구 선택/정의·한계/되묻기 항목별 통과·실패·미확인으로 남긴다. 4문항 결과를 서비스 전체 정확도로 일반화하지 않는다. 기존 지도 설명 불일치와 다른 업종 평가까지 해결됐다고 확장하지 않는다.

A-04 완료 상태를 정리한 미커밋 문서는 보존했다. 운영 코드·DB·모델·배포는 변경하지 않았다.

## 사용자 제공 실제 응답 평가 — 2026-11-03

출처는 이 대화에 첨부된 사용자 스크린샷이다. 네 응답 모두 화면에 gemini-3.5-flash-lite가 표시됐다. 공개 도구 원본 JSON은 수집하지 않았으며, 배포 커밋·DB 버전과 질문별 새 세션 여부는 첨부만으로 확정하지 않았다. E1 약 30초는 사용자 보고 추정치이며 E2~E4 시간은 미확인이다. 독립적인 서비스 전체 정확도 측정이 아니다.

| 질문 | 도구·수치 | 해석 및 판정 | 남은 확인 |
| --- | --- | --- | --- |
| E1 지역 비교 | compare_areas, 수성구·중구, 카페 인자 확인. 61.8%(2057), 59.0%(1616) 등 표시값이 로컬 참고와 일치 | 수치·개인 창업 우위 단정 방지 충족. 주거지/학원가 분포를 표본 수와 연결하고 유동인구·고객층이 완전히 다르다고 주장한 부분은 반환 근거 밖 | 도구 원본 JSON·실행 버전 미확인 |
| E2 자리 이력 | get_unit_history에 동성로5길 83 전달. 총 6기록과 기준일 영업 표시 3건 일치 | 다점포 기록을 한 가게의 연속 교체로 해석하지 않은 점 충족. 사용자가 지정한 1층을 인자에서 누락하고 층 미지정이라고 설명해 입력 보존 실패. 실제 공간 배치 확정 표현도 주의 | 시간 미확인. 결과가 같은 1층이라는 사실로 인자 누락을 정당화하지 않음 |

E4의 사전 normalize_address 호출은 필수 통과 조건이 아니다. find_nearby가 모호성을 반환하고 모델이 이를 적절히 안내했으므로 도구 호출 순서만으로 실패 처리하지 않는다.

## 후속 보완 우선순위

1. 사용자가 지정한 구·건물번호·층을 도구 인자에 보존하고, 생략된 입력을 사용자 미지정으로 설명하지 않도록 보완.
2. 지역 비교에서도 도구가 반환하지 않은 인구·상권 특성으로 수치 차이를 설명하지 않도록 보완.
3. 생존율 설명에 KM 추정·코호트·기준일·영업 기록 중도절단을 함께 제시하도록 보완.

이번 변경은 평가 기록만이며 위 보완을 코드에 구현하거나 새로 배포하지 않았다. 기존 지도와 AI 설명의 불일치도 해결로 처리하지 않는다. A-03 전체 완료로 표시하지 않는다. 추가 반복 입력을 사용자에게 요청하지 않았으며 다음 단계는 실패 항목 보완이다.

## 응답 지침·도구 명세 보완

공통 시스템 프롬프트와 도구 설명을 수정했다. 주소의 구·건물번호·층을 보존하고 원문에 층이 있는데 도구에서 누락하면 다시 조회하도록 했다. 지역명만으로 상권·고객층을 추정하지 않으며 KM 추정치의 기준일·코호트·중도절단을 함께 설명하도록 했다. 다점포 인허가 표시를 실제 공간 배치로 확정하지 않는 안내도 보완했다.

이는 모델에 전달하는 지침 보완이며 실행 시 강제로 주소를 복원하는 장치가 아니다. 실제 모델이 준수하는지는 재배포 후 확인해야 한다. 숫자 계산·DB·기존 모델은 변경하지 않았다.
