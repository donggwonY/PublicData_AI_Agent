# A-01 입력 변경과 기존 결과 재검증

> 후속 완료: 같은 날 [공유 DB v3 직접 검증](db_verification.md)을 수행했다. 아래 미연결 기록은 최초 로컬 검사 당시 상태다.

2026-10-21 · 김선경 · 로컬 이전/최신 스냅샷 비교 및 집계 재계산 완료. 공유 DB 직접 확인은 미수행.

## 기존 결과 사용 여부

- 동대구역 300m: 전체 732건·카페 42건, 동일행 제거 전체 724건·카페 41건. 최신 로컬 상가 자료로 재계산하여 기존 결과와 일치했다.
- 300m 최근접 배정: 1번 3건·2번 21건·3번 18건, 동일행 제거 시 3·20·18건. 500m 결과도 기존 근거와 일치했다.
- 상가·승하차·행정동 맥락 파일은 이전 스냅샷과 동일하고 출구 자료는 기존 결합 입력 해시 검증을 통과했다. 카페 지도와 과거 역별 탐색 결과는 기존 입력 시점의 결과로 보존할 수 있다. 이번에는 전체 상관분석이나 지도 화면을 다시 검증한 것은 아니다.
- 후보 업종 12개 비교표는 변경 전 stores 자료를 사용했음이 해시로 확인됐다. 현재 15업종 현황으로 사용할 수 없으므로 과거 비교자료로 표시하고, 새 업종 비교가 필요하면 정의를 갱신해 별도로 재계산해야 한다.
- 인허가 갱신이 상가 목록 갱신을 뜻하지 않는다. 기존 카페 수를 2026-10-13 또는 오늘의 영업 점포 수라고 표현하지 않는다.

## DB 확인 제한과 다음 단계

실제 프로세스 환경변수와 Git 제외 .env를 확인했으며 APP_DATABASE_URL 및 APP_READER_DATABASE_URL 모두 미설정이었다. 비밀값은 출력하지 않았다. 공유 프로젝트 uoiamnbkzlvlskngataq의 접속 계정·읽기 권한·app.current_version은 확인하지 못했고 DB 저장도 하지 않았다.

관리자에게 해당 공유 프로젝트의 최소 권한 읽기 전용 접속 정보를 받아 로컬 APP_DATABASE_URL에 설정한 뒤, 실제 대상·권한·현재 버전을 조회하고 이번 로컬 입력과 대조한다. 운영 app 변경이나 버전 전환은 하지 않는다.

## 재현

`.venv/Scripts/python.exe scripts/check_a01_refresh.py` — 입력 비교, 기존 해시 검증, 반경별 전체/카페 수 및 최근접 출구 배정 검증. 상세 입력 SHA-256은 refresh_check.json. 기존 평가표·지도·분석 수치는 덮어쓰지 않았다.
