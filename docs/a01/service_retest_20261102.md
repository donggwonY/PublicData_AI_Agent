# A-03 배포 후 재평가 — 2026-11-02

## 증거와 범위
김선경이 공개 앱에서 입력한 질문과 응답 스크린샷을 이 대화로 제공했다. 화면 모델 표시는 gemini-3.5-flash다. 에이전트가 브라우저에서 직접 실행하거나 도구 원본 JSON을 수집한 검증은 아니다. 화면만으로 실행 커밋·DB 버전은 확정하지 않는다. 원본 화면은 이 대화 첨부에 있으며 아래는 전사 요약이다.

세 번째 질문에 대해 두 응답 묶음이 제공되었다. 사용자는 입력 질문이 아래 Q3와 같음을 확인했다. 두 응답이 나온 실행 순서·재생성 여부는 확인되지 않았으므로 유리한 응답만 선택하거나 별도 독립 평가 횟수로 세지 않는다.

## 질문과 관찰
1. 동대구역 출구 주변 300m에 카페가 얼마나 있어? 500m로 넓히면?
   - 출구 좌표·합집합 도구가 서비스에 연결되지 않았다고 설명했다. 단일 대표 주소로 대체하지 않았다. 기능 한계 설명 통과이며 출구별 카페 수 계산 성공은 아니다.
   - 승하차 37,228명을 제시했지만 카페 수요·임대료를 직접 설명하지 못한다는 한계를 밝혔다. 이 수치는 이번에 원본 도구 결과와 재대조하지 않았다.
2. 300m 범위의 카페를 가장 가까운 출구에 하나씩 배정하면 어느 출구 쪽에 많아?
   - 최근접 출구 배정 기능 미연결을 설명하고 순위를 만들지 않았다. 한계 설명 통과.
   - 추천 질문에서 인허가 공백 후보를 공실 후보와 병기했다. 실제 공실 미확인이라는 구분을 후속 제안에도 유지해야 한다.
3. 동부로22길 9와 동부로 149의 주변 카페 수를 비교해 줘. 카페가 적은 쪽에 창업하면 더 유리할까?
   - 동부로22길 9: 원기록 39 → 동일행 제거 38 → 중심 건물 같은 주소 1 제외 37건.
   - 동부로 149: 원기록 44 → 동일행 제거 43 → 중심 건물 같은 주소 11 제외 32건.
   - 기존 저장 검증 결과와 일치하며 고유 건물 수는 미계산이라고 설명했다. 대표 층 선택 안내도 표시했다.
   - 카페 수만으로 창업 유리 여부를 단정하지 않았다.
   - 첫 응답은 미측정이라고 명시한 뒤 높은 수수료·임대료와 방문객 위주 동선을 단정했다. 다른 응답은 높은 임대료 단정을 없앴지만 고밀도 실내/유동 상권을 근거 없이 설명하고 최근 공실 후보를 제안했다. 따라서 미측정 항목 표현은 통과로 판정하지 않는다.
   - 화면 지도는 공백일수와 직전 업태를 표시했다. 코드 확인 결과 find_nearby의 recent_vacancies에 조회 중심을 더한 지도이며 카페 위치 지도가 아니다. 화면의 11개·10개를 카페 수로 해석하면 안 된다.

## 판정과 후속 보완
집계 의미·출구 기능 한계·창업 단정 방지는 개선 확인. 상권 특성·공실 표현은 보완 필요. A-03 전체 완료로 판정하지 않는다. 사용자 독립 사용성 평가는 아직 수집하지 않았다.

- 공통 프롬프트에 주의점·추천 질문까지 근거 기준을 적용하고 근거 없는 상권 특성 문단을 생략하도록 추가했다.
- 공백 후보를 실제 공실 후보와 동의어로 쓰지 않도록 구체적 제안 문구를 지정했다.
- find_nearby 결과에 공백 후보 정의를 추가하고 지도 위에 카페 위치 지도가 아니라는 제목·설명을 표시했다.
- 모델·DB·집계 수치는 변경하지 않았다. 이번 로컬 보완의 실제 LLM 효과는 아직 미검증이며 염동권의 재배포 후 같은 질문으로 확인해야 한다.
