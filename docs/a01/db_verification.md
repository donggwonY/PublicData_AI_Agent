# A-01 공유 DB v3 검증 결과

2026-10-21 · 김선경 · 공유 DB 직접 조회 및 동대구역 카페 재계산 완료.

## 결론

기존 동대구역 카페 집계는 공유 DB v3에서도 동일하다. 카페 수·출구별 분포와 지도에 사용한 상가 입력을 변경할 필요는 없다. 지도 화면 자체와 실제 서비스 AI 응답은 이번에 재시험하지 않았다.

## 확인 범위

- 대상: Bigdata_platform / JunseokNoh's Project (`uoiamnbkzlvlskngataq`), `app` 스키마.
- `app.current_version`: 3. `dataset_versions.status`: current, `reference_date`: 2026-10-13.
- 사용자가 기존 postgres 계정으로 조회를 진행하도록 요청했다. 이는 전용 읽기 계정이 아니며, 이번 검증 스크립트는 `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY` 후 `transaction_read_only=on`을 확인하고 실행했다. 연결 URL 옵션만으로 읽기 전용 상태가 보장되지 않아 명시적 트랜잭션을 사용했다. 이 결과를 다른 프로그램까지 읽기 전용이라고 해석하지 않는다.
- DB 변경·운영 버전 전환·서비스 배포 없음. 결과는 로컬 문서에만 저장했으며 GitHub 푸시는 하지 않았다.
- 작업 시작 시 pull 도구가 미커밋 자료 때문에 중단되어 자료를 보존한 채 fetch로 확인했다. HEAD와 origin/main 차이는 0/0이었다.

## 전체 입력 대조

DB 자료는 `_row` 순서로 조회하고, 적재 메타데이터의 자료형으로 복원한 뒤 로컬 Parquet와 비교했다. 단순 행 수 비교가 아니라 모든 열의 값·결측·행 순서·자료형을 정확 비교했다.

| 자료 | DB 행 수 | 로컬과 비교 |
| --- | ---: | --- |
| poi | 118,357 | 전체 일치; 주소·위도·경도·업종 포함 |
| station_traffic | 94 | 전체 일치 |
| area_context | 150 | 전체 일치 |
| stores | 225,858 | 행 수만 확인; 이번 전체 내용 비교 대상 아님 |

출구 좌표는 기존 공식 출구 자료 `station_locations.json`을 사용했다. 출구 좌표를 DB에서 새로 수집하거나 현장 확인한 것은 아니다.

## DB 자료로 직접 재계산

카페는 `cat_s == '카페'`. 어느 한 출구에서라도 직선거리 반경 안에 들면 포함하고, 출구별 분포는 가장 가까운 출구 하나에 배정한다. 동일행 제거는 DB 관리 열을 제외한 상가 원래 열 전체를 기준으로 한다.

| 반경 | 전체 상가 기록 | 동일행 제거 전체 | 카페 기록 | 동일행 제거 카페 |
| --- | ---: | ---: | ---: | ---: |
| 300m | 732 | 724 | 42 | 41 |
| 500m | 1,294 | 1,272 | 72 | 70 |

| 최근접 출구 | 300m 카페 기록 | 동일행 제거 | 500m 카페 기록 | 동일행 제거 |
| --- | ---: | ---: | ---: | ---: |
| 1번 | 3 | 3 | 11 | 10 |
| 2번 | 21 | 20 | 38 | 37 |
| 3번 | 18 | 18 | 23 | 23 |

기존 300m/500m 집계와 모두 일치했다. 300m 동일행 제거 기준 2·3번 출구에 최근접 배정된 기록은 38/41건이다. 이는 출구별 유동인구·매출 또는 출구 이용 방향을 입증하지 않는다.

## 한계와 다음 업무

- DB 묶음의 기준일 2026-10-13이 모든 보조자료의 조사일을 뜻하지 않는다. 카페 41건을 오늘 실제 영업 중인 41개 점포로 표현하지 않는다.
- 인허가 자료는 이전 대비 변경됐다. 기존 12개 후보 업종 비교표는 이전 인허가 입력을 사용한 과거 자료이므로 현재 업종 현황표로 사용하지 않는다.
- 전체 역 상관분석, 주소별 인허가 이력 결합, 실제 서비스 AI 평가, 지도 화면 재시험은 이번 범위에 포함하지 않았다.
- 다음 추천: A-03 질문 3개에 실제 서비스가 내놓는 답변을 이번 검증 근거와 비교해 평가한다. 평가 세트 작성과 실제 평가 완료를 구분한다.

## 팀 공유 문안

> A-01 동대구역 카페 분석을 공유 Supabase DB v3 기준으로 재검증했습니다. 상가·역 이용량·지역 맥락 자료는 로컬 분석 입력과 전체 내용이 일치했고, 출구 주변 300m 카페 42건(동일행 제거 41건)과 출구별 분포도 그대로였습니다. 기존 지도·집계는 유지하며, 실제 영업 현황이나 매출을 뜻하지 않는다는 한계도 정리했습니다. DB 수정이나 서비스 반영은 하지 않았고, 다음으로 A-03 실제 서비스 답변 평가를 진행할 예정입니다.

## 재현

프로젝트 가상환경에서 `python scripts/check_a01_db.py` 실행. `APP_DATABASE_URL`은 프로세스 환경변수가 로컬 `.env`보다 우선한다. 대상 프로젝트를 검사하고 DB 실패 시 로컬 자료로 대체하지 않는다. 상세 검증 결과·실행 시각·로컬 입력 해시는 [db_verification.json](db_verification.json)에 저장한다.
