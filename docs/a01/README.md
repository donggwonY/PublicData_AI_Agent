# A-01 역 이용량과 주변 업종 구성

담당: 김선경 · 시작: 2026-10-12 · 상태: 진행(질문 구체화·자료 가용성 확인)

## 학생이 선택한 질문

역 이용량과 주변 업종 구성은 어떤 관계가 있는가?
학생 가설(2026-10-12): “오가는 사람이 많으니 카페/간편식 비중이 높을거 같다.”

검증할 방향: 역 이용량이 많을수록 주변 상가 중 카페·간편식 업종의 비중이 높은지 확인한다. 아직 검증된 결과가 아니다. 300m를 기준, 500m를 비교 범위로 선택했다. 학생이 전체 상가 분모를 선택했다. 카페와 김밥/만두/분식·버거·토스트/샌드위치/샐러드·빵/도넛을 사용한다.

현재 작업판·플레이북·D-01 완료 보고서·D-02 인계 문서에는 역 좌표 신규 확보가 김세은의 별도 과업으로 명시되어 있지 않다. A-01의 공간 결합 준비 단계에서 확보·검증할 입력으로 다룬다. 문서 밖에서 진행 중인 팀원 작업 여부는 확인하지 않았다.

2026-10-12 공식 역 대표좌표 94행과 출구 좌표 429행을 확보했다. 승하차 94행 중 이름·호선 기준 92행이 연결되지만, 대표좌표와 출구 좌표가 크게 다른 역이 있어 위치 검증은 완료하지 않았다. [확보·검증 보고서](station_audit.md)와 [역별 결과·출처 해시](station_audit.json)를 참고한다. 기존 `service/core/tools.py`의 역명 접두어 연결은 실제 주변 상권의 근거로 사용하지 않는다.

## 다음 단계

좌표 검토 후속: [분석 위치 선택 기록](location_resolution.md). 대표좌표 불일치 5건은 원본 보정 대신 공식 출구 좌표로 우회했다. 출구 기반으로 승하차 94항목 중 90항목을 연결했고, 나머지 4항목은 누락/이름 확인 대상으로 남겼다. 좌표계·경계 지역 자료 범위·환승역 중복 문제는 별도로 유지한다. 역명 2건의 근거와 도분초 표기 가설도 기록했다.

1. 학생 가설·업종 분류·전체 상가 분모 선택 완료. [첫 가설 비교](hypothesis.md)와 [산점도](hypothesis.png) 기록.
2. 출처·기준일·좌표계가 확인되는 역 위치 자료를 확보하고 역명·호선·환승역 연결을 검증한다.
3. 출구 직선거리 300m 기준·500m 비교를 계산했다. 같은 역 출구와 환승역 호선을 통합하고 역 사이 중복은 기록했다. [공간 결합 결과](poi_join.md) 참고.
4. 표본 역의 공간 결합·누락·중복을 확인한 뒤 업종별 건수와 구성비를 비교한다.

오늘의 작은 산출물은 결합 기준표와 표본 역의 결합 가능 여부 기록이다. 좌표 확보 전에는 상관관계나 주변 업종 결과를 만들지 않는다. 승하차 합은 고유 방문자 수가 아니며 관계가 나타나더라도 인과 효과로 해석하지 않는다.

## 학생 해석과 시간대 후속 탐색

선경 님은 “카페는 커피/음료만 있으니까 배 채울려면 간편식이 더 관련이 있을테니까?”라고 해석했다. 이동 중 식사 수요라는 설명 가설로 기록하며 구매 목적을 확인한 사실로 취급하지 않는다.

[시간대 비교](time_slots.md): 환승역을 제외한 80개 역, 300m 전체 상가 분모에서 간편식 비중과 점심 하차 비중의 순위상관 -0.260, 17~20시 하차 비중은 +0.399. 500m·동일행 제거·소규모 상권 제외에서도 부호 유지. 시간대 하차 비중은 이용객 수·식사 목적과 다르다. 후속 결과에 대한 학생 해석과 시점/좌표계/경계 확인은 남아 있다.

## 행정동 맥락 후속 확인

[주거지역 참고 지표 비교](residential_context.md): 300m 주변 상가의 과반이 한 행정동인 66개 역에서 저녁 하차 비중 상위 그룹은 기존 규칙 주거상권 8/32, 하위는 4/34였다. 그러나 500m·대표동 비중 >80%에서는 1/10 대 3/11로 방향이 반대다. 행정동 전체 인구는 역 주변 인구나 밀도가 아니고 기존 분류는 음식 구성에 의존하므로 주거/귀가 원인 설명을 확정하지 않는다. 독립적인 주거 건물·격자 인구 등의 확인이 필요하다.

## 프로젝트에 남길 범위와 상담 사례

[상담 평가표](consultation_evaluation.md)에 역 전체 카페 수, 출구별 분포, 예시 주소 비교 질문 3개와 통과 기준을 정리했다. A-03 평가 세트 작성은 시작했으며 실제 서비스/LLM 실행·채점은 미수행이다.

사용자와 범위를 축소했다. [동대구역 카페 상담 사례](consultation_case.md)를 현재 산출물의 중심으로 삼는다. 역 출구 주변 업종 집계·좌표/역명 품질 기록을 남기고, 주거용 건물·격자 인구 추가 수집과 귀가 원인 연구는 보류한다. 기존 상관 분석은 탐색 기록으로만 보존한다.

300m 카페 42/732건(5.74%), 동일행 제거 시 41/724건. 500m 카페 72/1,294건(5.56%). 원본 재계산 검증 완료. 실제 점포 주소를 받으면 기존 find_nearby·get_unit_history로 이어가는 흐름을 정리했다. 서비스 도구 구현·실제 LLM 평가·배포는 수행하지 않았다.
