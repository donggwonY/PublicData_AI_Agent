# A-03 배포 후 실제 서비스 재평가

2026-10-29 · 김선경 담당 · 실행·판정 Codex. 학생 사용성 평가 및 독립 채점은 미실시.

## 결론

출구 기능 미지원 안내와 대표 층 선택 고지는 개선됐다. 그러나 기록 수·중복 제거·같은 건물 제외의 의미를 혼동하고, 측정하지 않은 수요·임대료를 단정하는 문제가 남았다. 전체 통과로 판정하지 않는다. 이전 평가와 보고서는 수정하지 않고 이 후속 기록으로 분리한다.

## 실행 조건

https://pubdai.streamlit.app/ 에 새 브라우저 탭과 빈 대화 세션을 열어 기존 질문 3개를 동일한 순서로 각 1회 입력했다. 질문 2·3에는 앞선 대화 이력이 포함된다. 정답 자료는 제공하지 않았다. 화면 기준일 2026-10-13, db v3, 모델 gemini-3.5-flash. 작업판의 2026-10-29 배포 기록 이후 실행했지만 공개 화면에서 정확한 Git SHA를 직접 확인하지는 않았다. 반복 성능·전체 정확도 추정은 하지 않는다.

질문 2의 제안 질문에는 여전히 ‘현재 공실 상태’라는 표현이 있어 인허가 공백과 실제 공실을 구분하는 표현 점검이 필요하다. 질문 3의 ‘매출·임대료 데이터는 공공 데이터로 제공되지 않는다’ 역시 서비스 미보유와 자료 자체 부재를 구분해야 한다.

## 집계 정의 대조

공개 응답의 도구 호출 인자를 로컬 Parquet로 재현했다. 공개 도구 JSON 전체를 확보한 것은 아니며, 아래는 로컬 재현 근거다.

| 중심 주소·반경 | 원기록 | 동일행 제거 | 중심과 같은 주소 | 같은 주소 제외 |
| --- | ---: | ---: | ---: | ---: |
| 동대구로 550·300m | 30 | 30 | 4 | 26 |
| 동대구로 550·500m | 56 | 55 | 4 | 51 |
| 동부로22길 9·300m | 39 | 38 | 1 | 37 |
| 동부로 149·300m | 44 | 43 | 11 | 32 |

같은 주소 제외는 동일행 제거 후 **중심 건물과 도로명·건물번호가 같은 기록만 제외**한다. 남은 기록을 서로 다른 건물 하나씩으로 합치는 연산이 아니다. 따라서 26/51을 고유 주소 수라고 하거나, 37개가 각각 다른 건물이라고 하는 설명은 도구 정의와 맞지 않는다. 39-1=37, 44-11=32처럼 보이는 혼란을 막으려면 동일행 제거 중간값 38/43도 명시해야 한다.

대표 층 선택 고지는 두 주소 모두 포함됐다. 동부로 149는 지하 1층을 사용했다. 새 코드에서는 정확한 건물 하나로 좁힌 뒤 대표 층을 선택하므로, 이전 평가의 ‘무조건 층을 먼저 질문해야 한다’는 기준으로 실패 처리하지 않았다. 다른 건물 후보가 여러 개인 경우의 선택 UI는 이번 세 질문으로 검증하지 않았다.

## 다음 작업

1. 도구 결과 설명에서 ‘동일행 제거’와 ‘중심 건물 제외’를 명확히 분리하고 고유 건물 수로 바꾸어 말하지 않도록 보완한다.
2. 확인하지 않은 집객력·수요·임대료는 미확인으로 표시한다. 공공데이터 자체가 없다는 일반화도 피한다.
3. 수정 후 같은 질문으로 재확인하고 학생 사용성 의견을 별도로 받는다. 이번에는 코드·DB·배포를 변경하지 않았다.

## 재평가 후 로컬 보완

후속 요청으로 `find_nearby`에 실제 계산값을 넣은 `count_explanation`과 고유 건물 수 미계산 표시를 추가했다. 기존 수치 필드는 유지한다. 중심 건물 제외가 다른 건물의 여러 카페를 합치지 않는다는 점을 명시하며, 수요·매출·임대료·수수료·동선의 미측정 한계를 도구 결과와 공통 시스템 프롬프트에 전달한다. 도구 설명도 같은 정의로 맞췄다.

같은 중심 기록의 중복 1건과 같은 외부 건물의 서로 다른 카페 2건을 넣은 회귀 사례에서 원기록 4 → 동일행 제거 3 → 중심 1건 제외 후 2건이 유지되는지 검사한다. 이 검사는 고유 건물 수 1개로 오해해 집계를 바꾸는 회귀를 방지한다.

이는 도구 계약·프롬프트 보완이며 실제 Gemini가 지침을 지키는지 보장하지 않는다. 공개 앱의 위 답변은 수정 전 증거로 유지한다. 염동권의 배포 후 새 세션에서 같은 질문으로 실제 응답을 재검증해야 한다. DB 변경·배포는 수행하지 않았다.

검증: `python -m unittest tests.test_core_units tests.test_a03_regressions tests.test_area_parsing` 23개 통과. `python -m tests.smoke_test` ALL PASSED 0(의도한 오류 경로 포함). `git diff --check` 통과. 전체 discovery는 최초 Streamlit 미설치로 화면 검사 2개 모듈 import 실패; 지정 버전 1.64.0을 로컬 가상환경에 설치한 뒤 재시도했으나 화면 검사에서 장시간 완료되지 않아 중단했다. 전체 UI 검사 통과로 기록하지 않는다. 운영 의존성 파일은 변경하지 않았다. 실제 Gemini 재평가는 아직 하지 않았다.

후속 검증: 중단 원인을 추적한 결과 샌드박스 임시 디렉터리 PermissionError 및 asyncio 로컬 socketpair의 accept 대기를 확인했다. 승인된 제한 밖 실행에서 `python -m unittest discover -s tests -p "test_*.py"` UI 포함 28개가 11.710초에 모두 통과했다. 이 문제 때문에 서비스 코드를 변경하지 않았다. 앞선 스모크 통과와 함께 main 반영 검증을 완료했으며, 실제 모델 응답 재검증은 여전히 배포 후 과제다.
