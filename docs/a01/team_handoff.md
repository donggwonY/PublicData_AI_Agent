# 김선경 A-01·A-03 팀 공유

## 이번 결과

동대구역 주변 상담에서 카페 개수와 위치를 함께 설명할 수 있도록 공식 출구 좌표와 상가 자료를 결합했다. 사용자가 ‘어디에 있는지 지도나 위치가 필요하다’고 선택한 피드백을 반영해 카페 선택·주소·최근접 출구 거리·도로/건물 이름을 보여주는 [지도](cafe_map.html)를 준비했다. HTML 파일을 내려받아 브라우저로 열 수 있으며 지도 라이브러리 로딩에는 인터넷 연결이 필요하다.

- 보유 1·2·3번 출구의 직선거리 300m 합집합: 카페 기록 42건, 동일행 제거 41건.
- 최근접 출구 배정: 1번 3건, 2번 21건, 3번 18건. 동일행 제거 시 2번은 20건.
- 같은 좌표를 묶으면 지도상 위치는 23개다. 점 개수와 카페 기록 수를 구분해야 한다.
- 예시 주소 비교에서는 같은 주소의 카페를 포함/제외하면 순서가 바뀌어 건물 내부와 외부 기록을 구분할 필요가 있었다.

## 평가와 남은 일

[상담 평가표](consultation_evaluation.md)에 질문 3개·정답 근거·통과 기준·실패 예시를 정리했다. 답변 생성과 AI 자체 검토, 지도 표시·선택 동작 검증까지 수행했다. 독립 사용자 평가·서비스 모델 실행은 하지 않았다. 로컬 서비스 API 키가 없어 실제 Gemini 실행 결과가 없다.

서비스 코드와 배포에는 반영하지 않았다. A-01과 A-03은 진행 상태를 유지한다. 팀에서 결정할 사항은 **역 주변 카페 분포 지도를 상담 기능에 사용할지**, 사용한다면 **역 출구 주변 조회와 후보 점포 주소 조회를 어떻게 구분할지**다.

상가 설정 기준은 2026년 6월이며 원본 관측일·현재 영업은 검증하지 않았다. 출구 자료는 2024년 기준으로 현재 운영 상태·좌표계 확인이 남아 있다. 최근접 출구는 실제 보행 동선이나 고객 유입이 아니다. 개수만으로 매출·창업 성공·추천 입지를 판단하지 않는다. 주거 원인 연구와 추가 수집은 보류했다.

## 재현과 검증

Python 3.12 환경에서 `scripts/build_a01_consultation_case.py`, `scripts/analyze_a01_dongdaegu_exits.py`, `scripts/compare_a01_example_addresses.py`로 원본 해시·반경 집계·중복 처리·배정 합계를 검증한다. 지도는 `scripts/build_a01_cafe_map.py <출력 경로>`와 `scripts/dongdaegu-map.template.html`로 생성한다. 분석 원본은 Git 제외 경로 `data/raw/a01/`에 보관하며, 출처는 각 JSON과 `cafe_map_sources.json`에 기록되어 있다. 다른 환경에서 지도를 재생성하려면 해당 원본을 확보해야 한다. 공유용 HTML에는 표시용 데이터가 포함되어 있다.

일반 화면과 390px 화면에서 지도 배치 및 카페 선택 시 상세 정보 변경을 확인했다. 기존 상관 분석은 탐색 기록으로 보존하며 서비스 성능이나 창업 추천 근거로 해석하지 않는다.
