# 멘티 협업 및 Git 작업 흐름

## 담당 초점

| 멘티 | 우선 담당 | 검토 가능한 산출물 |
| --- | --- | --- |
| 염동권 | 화면·서버·저장소 계약·분석 결과 통합·배포 | 재현 가능한 실행/배포 절차, 데이터/모델 조회 인터페이스, 검증·장애 대응 |
| 김세은 | 데이터 품질·정의·탐색 분석·생존/결과 모델 | 데이터 사전·품질표, 코호트/중도절단 분석, 기준선과 예측 검증 |
| 김선경 | 보조 데이터 결합·지역/시간 ML·AI 도구 평가 | 결합/EDA 기록, 선택한 ML 질문의 실험, 도구·답변 평가표 |

각자 자기 담당 밖의 코드도 수정할 수 있습니다. 다만 지표 정의 변경은 김세은, AI 답변 기준 변경은 김선경, 배포 설정 변경은 염동권과 함께 확인합니다. 발표 범위와 중요한 설계 결정은 관리자가 조율합니다.

에이전트는 [멘티 플레이북](MENTEE_PLAYBOOK.md)의 질문과 완료 기준을 활용하고, [작업판](WORKBOARD.md)의 실제 증거를 보고 다음 일을 제안합니다. 세은과 선경은 모두 데이터 분석·ML을 직접 수행한다. 선경을 프롬프트 작성만 하는 역할로 축소하지 않는다.

## 작업 단위

1. 개발 세션을 시작하면 Codex의 `$pull` 또는 Claude Code의 `/pull`을 실행합니다. 에이전트가 원격 `main`을 가져와 fast-forward가 가능할 때만 반영합니다. 작업 파일이 수정돼 있거나 이력이 갈라졌다면 덮어쓰지 않고 해결 방향을 안내합니다.
2. 이슈 또는 작업 메모에 목적, 완료 조건, 담당, 관련 데이터 기준일을 적습니다.
3. 각 멘티는 기본적으로 `main`에서 작업합니다. 작업을 공유할 때 Codex의 `$commit-push` 또는 Claude Code의 `/commit-push`를 실행합니다.
4. 에이전트가 변경 내용과 필요한 검증을 확인하고 커밋한 다음 원격 `main`을 다시 가져옵니다. 다른 멘티의 커밋이 앞서 있으면 fast-forward하거나 자신의 커밋을 최신 이력 위에 rebase합니다.
5. 충돌이 나면 에이전트가 양쪽 변경을 읽고 통합해 다시 검증합니다. 이후 `main`에 강제 푸시 없이 반영하고 커밋·검증 결과를 알려줍니다. 판단이 어려운 충돌이나 권한 오류만 사람에게 전달합니다.

## 코딩 에이전트와 Git 게시

`pull` 스킬은 `scripts/pull_main.py`로 개발 시작 전 원격 `main`을 확인합니다. `commit-push` 스킬은 학생 대신 `scripts/commit_push.py`의 커밋·동기화·푸시 단계를 실행합니다. 동기화 후와 충돌 해결 후에는 관련 검증을 다시 합니다. 푸시 직전에 원격이 바뀌면 다시 동기화하며, 실패가 반복되면 현 상태를 보존하고 원인을 설명합니다. 일상 작업에는 PR을 사용하지 않습니다.

GitHub 토큰은 개인별 fine-grained PAT로, 이 저장소의 `Contents: Read and write`만 부여합니다. 초기 설정 스킬이 질문과 로컬 저장을 처리하며, 토큰을 명령줄 인자·원격 URL·커밋에 넣지 않습니다. `.env`와 `.mentee/profile.json`은 로컬 전용이며 Git에서 제외됩니다. 설정 스크립트는 pre-push 훅을 활성화해 비밀 파일과 토큰 형태 문자열이 포함된 커밋의 푸시를 거부합니다. `.env`를 분실하거나 노출하면 GitHub에서 토큰을 폐기하고 새로 만듭니다.

## 관리자 체크포인트

분석 정의·데이터 출처 변경, 모델·할당량 변경, 공개 배포와 비용 발생, 사용자 데이터 저장 정책은 관리자가 이해할 수 있도록 문서와 테스트 결과를 남깁니다. 설계가 바뀌면 `docs/IMPLEMENTATION_DESIGN.md`를 함께 수정합니다. 이런 결정을 멘티가 단독으로 확정하기 어렵다면 게시 전에 관리자와 논의합니다.

## 코딩 에이전트 지침 관리

공통 지침은 `AGENTS.md`만 수정합니다. `CLAUDE.md`의 `@AGENTS.md`가 동일한 내용을 Claude Code에 전달합니다. 프로젝트 스킬은 `.agents/skills/<이름>/SKILL.md` 한 곳에 작성하고 `python3 scripts/link_skills.py`로 `.codex/skills/<이름>`과 `.claude/skills/<이름>` 링크를 생성합니다. 스킬 이름·설명은 두 도구에서 이해할 수 있는 공통 YAML 필드만 사용하고, 실행 명령은 둘 다 사용할 수 있는 로컬 스크립트를 가리키게 합니다. 새 스킬을 추가하면 두 경로가 같은 원본을 가리키는지 확인합니다.
