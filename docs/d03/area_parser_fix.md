# 면적 숫자 변환 수정과16건 대조

## 수정과 실제 자료 검증

배치의 면적 변환을 엄격한 천 단위 구분 처리로 수정했다. 1,048.35는1048.35로 읽고 12,34 같은 잘못된 쉼표는 결측을 유지한다. 일반 숫자·0·음수·누락의 기존 의미는 보존한다.
2010~2021 로컬 원본 대응 범위에서55개 값을 복구 가능함을 dry-run으로 확인했다. 복구 범위 1,004.99~3,147.92㎡. 기존 숫자 31,108건은 동일. 값이 크다는 이유만으로 상한을 두거나 삭제하지 않았다.

## 16건과 미연결1건

16건은 원본 값 자체가 숫자로 잘 읽히므로 쉼표 오류로 설명되지 않는다. 예: 가공99.24㎡/현재원본64.88㎡. 현재 보유 CSV와 기존 Parquet는 동일 원본 버전이라고 확인되지 않았으며, 실제 면적 변경/원본 정정/당시 가공 차이 중 무엇인지는 미확정이다. 당시 배치 입력 원본과 변경 이력이 없으므로 자동 덮어쓰기하지 않는다. 상세 관리키·양쪽 값·현재 수정일과 원본 미연결1건은 JSON에 기록했다. 원본 수정일만으로 면적 변경 시점/정답을 추정하지 않는다.

## 영향 범위와 검증

파서3개+core14개 총17개 단위검사, 서비스 smoke ALL PASSED0. 기존 D-03 stores 해시 유지 확인. 기존 로컬 분석 패키지 환경에서 검사했으며 배포 고정 환경 재현은 별도다. 전체 배치 재생성·DB 적재·공개 배포·푸시는 미수행. 다음 배치부터 새 파서가 적용되며 현재 앱의 면적 값은 아직 바뀌지 않았다.

개업 당시 면적임을 확인한 것은 아니어서 예측 모델에는 추가하지 않았다. [세부 대조](area_parser_fix.json). 재현: `python scripts/verify_d03_area_fix.py`.
