# 면적·좌표 누락을 포함한 전체 대상 평가 계획

2026-11-03. 실행 전 계획이며 신규 성능 결과가 아니다.

## 질문과 대상

면적·좌표가 없는 일반음식점까지 포함해 개업 후365일 이내 폐업·취소·말소 신고를 예측할 때, 단순 학습 평균보다 확률 오차를 줄일 수 있는가? 기존 양수면적·좌표 유효 표본만의 결과를 전체로 확대하지 않는다.

기존 stores.parquet 스냅샷과 사건 정의를 유지한다. 개업일·365일 관찰 기회가 있는 일반음식점이 대상이며 면적/좌표 누락을 이유로 제외하지 않는다. 가공 전에 제외된 원천 기록까지 복원한 전체 모집단이라는 뜻은 아니다.

## 최소 비교

1. 기준선: 해당 학습기간 전체의 신고 비율을 모든 평가 행에 동일하게 부여.
2. 후보: 업태·구군·개업 월만 사용하는 로지스틱 회귀(C=1, max_iter=2000, seed0). 범주 누락은 별도 값, 미관측 범주는 무시하며 인코더는 학습 행에서만 적합.

면적·좌표·누락 여부·현재 영업상태·폐업일·수정일을 입력에 넣지 않는다. 폐업일/상태는 정답 생성에만 사용한다. 수정일로 누락이 발생한 시점을 추정하지 않는다. 범주·주소 역시 당시 상태 보장 미확인 한계는 남는다.

## 시간 분리와 판정

학습2010~2013/평가2015~2016, 학습2010~2015/평가2017~2018, 학습2010~2018/평가2020~2021. 각 학습 행의365일 관찰 종료가 평가 시작보다 앞서는지 확인한다. 반복 사용한 과거 기간의 후속 탐색이며 독립 시험이 아니다. 2023~2025는 이번 계획에서 예측 재채점하지 않는다.

세기간 각각 Brier·log loss·평균예측·실제신고비율·표본/사건수를 보고한다. 세기간 모두 두 오차가 같은 전체표본 기준선보다 작아야 후속 검증 후보로 남긴다. 개선 실패 시 누락표본을 다시 제거하거나 다른 모델/계수를 즉시 탐색하지 않는다.

## 포함·제외 그룹의 진단

전체 평가와 함께 좌표 부적합 / 좌표 유효이나 면적 부적합 / 둘 다 유효의 상호 배타적 그룹을 보고한다. 이 구분은 사후 진단에만 쓰고 모델 입력·모델 선택에 사용하지 않는다. 기존 면적 복구 규칙을 재사용하며 원본과 가공값이 다른 두 건을 자동 덮어쓰지 않는다.

그룹별 표본·사건·두 오차와 구군·업태 분포를 확인한다. 전체표본·사건·가중오차가 그룹 합과 일치해야 한다. 평가 대상이 다른 과거 모델 점수를 직접 순위 비교하지 않는다. 기존 면적 모델과의 비교가 필요하면 동일 포함표본에서 별도로 비교하는 후속 설계를 한다.

## 실행 전 확인과 다음 단계

- 과거 기본 모델의 대상 필터·저장 결과가 이번 전체대상과 동일한지 먼저 확인한다. 이미 동일한 비교가 있으면 재학습 대신 저장 결과를 활용하고, 없는 그룹 진단만 추가한다.
- 현재 날짜의 새로운365일 관측 가능 기록이 생겼다고 가정하지 않는다. 고정 스냅샷 기준일과 입력해시를 확인한다.
- 원본키·중복·날짜 경계·입력/정답 분리·학습/평가 비중복·확률·수렴·그룹 합계를 검증한다.
- 모델 분기(면적 있음/없음)는 누락 시점이 불명확하므로 이번에 구현하지 않는다. 이 검토만으로 혼합 서비스 정책을 채택하지 않는다.

실행·DB 적재·운영 변경 없음. 성능 개선이 없어도 기존 모델이 설명하지 못했던 대상 범위를 명확히 하는 것이 이 점검의 산출물이다.


## 기존 실험 중복 확인 — 2026-11-03

scripts/fit_d03.py는 면적·좌표 필터 없이 일반음식점2010~2018로 학습하고2020~2021을 평가한다. 입력 업태·구군·개업 월, C=1 등의 설정이 이번 계획과 일치한다. 따라서2020~2021 전체 점수는 validation.json을 재사용할 수 있다. 다만 기존 target은 일수<=365이고 이번 계획은0~365이므로 실행 전 대상 내 음수기간 부재 확인이 필요하다. 원본 해시·실제 표본 동일성도 다시 확인해야 한다.

scripts/fit_d03_expanded.py의3기간 비교는 make_features에서 유효좌표만 남긴다. 따라서 그 결과를 좌표 누락 포함 전체 대상 결과로 대체하지 않는다. 기존 첫 검증에는 면적·좌표 제외 그룹별 예측 결과가 저장돼 있지 않다.

결론: 전체 계획을 새 실험으로 반복하지 않는다.2020~2021 전체 기존점수는 참고로 재사용하고,2015~2016/2017~2018 전체대상 및3기간 누락그룹 진단만 추가 계산 대상이다.2020~2021 그룹별 진단에는 동일 설정의 예측 복원이 필요하며 기존 전체점수 재현을 통과해야 한다. 이번 중복 점검에서는 재학습하지 않았다.

## 실행 상태 — 2026-11-03

추가 비교 코드 scripts/audit_d03_full_coverage.py를 작성하고 구문 검사를 통과했다. 실행은 기존 service/.venv의 sklearn을 불러오는 단계에서 Windows 애플리케이션 제어 정책의 DLL 차단으로 중단됐다. 학습·평가 전이므로 새 결과는 없다. 기존2020~2021 결과만 유효하며 신규 두 기간/누락그룹 진단은 미완료다. 보안 정책 변경·차단 우회·반복 재시도는 하지 않았다. 허용된 분석 환경에서 실행 필요.


## 팀원 실행 안내

저장소 루트에서 분석 의존성이 설치된 Python으로 `python scripts/audit_d03_full_coverage.py`를 실행한다. numpy/pandas/pyarrow/scikit-learn/scipy가 필요하다. 로컬 실행은 import 단계에서 차단되어 코드 구문 검사만 완료했으며 실제 실행 검증은 팀원 환경에서 필요하다.

필수 입력은 저장소의 service/data/processed/stores.parquet 및 meta.json, 기존 docs/d03 결과/계획, 원본 식품_일반음식점_대구광역시.csv다. 현재 코드는 저장소 루트의 두 단계 상위 아래 `상권분석 데이터/식품_일반음식점_대구광역시.csv`를 찾는다. 원본 CSV는 Git에 포함되지 않으므로 최신 main만 받아서는 부족할 수 있다. 파일 위치가 다르면 rp 경로를 실제 원본 위치로 수정하되 기존 해시 검사를 삭제하거나 기대값을 바꾸지 않는다.

원본 해시는 docs/d03/area_complete.json의 hashes.raw와 같아야 한다. 다른 파일이면 실행을 중단하고 입력 버전을 맞춘다. 성공 시 docs/d03/full_coverage.json 및 full_coverage.md가 생성된다. 실패 시 오류를 공유하며 결과가 생성됐다고 기록하지 않는다. DB 연결·운영 데이터 수정·배포는 없다.
