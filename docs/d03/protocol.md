# D-03 첫 예측 실험 계획

작성일 2026-10-17. 에이전트의 추천안을 바탕으로 일반음식점 첫 실험을 진행한다. 15개 분석 그룹 규칙은 유지하며 이번 모델은 일반음식점만 대상으로 한다.

## 질문과 관측 단위

개업 시점에 확보 가능하다고 가정한 업태·구군·개업 월 정보로, 일반음식점 인허가의 개업 후 365일 이내 폐업·취소·말소 신고 여부를 예측할 수 있는가?

한 행은 인허가 1건이며 고유 가게·사업자와 같다고 보장하지 않는다. 원본은 최신 스냅샷이므로 당시 업태·주소가 현재와 같았는지는 미검증이다. 따라서 이번 실험은 사후 데이터 기반 기초 실험이며 실제 개업 당시 예측 성능으로 과장하지 않는다. 사건일·상태는 정답 생성에만 사용한다.

## 고정한 시간 분할

| 구분 | 개업 연도 | 표본 수 | 목적 |
| --- | --- | --- | --- |
| 학습 | 2010~2018 | 22,960 | 전처리·계수·기준 폐업 비율 학습 |
| 검증 | 2020~2021 | 5,681 | 후보 선택·오류 점검 |
| 최종 평가 | 2023~2024 | 5,837 | 선택 완료 후 성능 보고 |

2019년은 학습 결과 관측에 필요한 간격, 2022년은 검증 결과 관측에 필요한 간격으로 둔다. 2025년은 일부 연도만 365일 추적 가능하므로 첫 비교에서는 사용하지 않는다. 365일 추적이 끝난 뒤 다음 구간이 시작됨을 코드로 확인했다. 최근 개업 중 일찍 폐업한 행만 추가하지 않는다.

이 분할은 첫 보수적 실험이며 유일한 최선의 분할은 아니다. 2020~2021년 특수 상황과 시간에 따른 변화 때문에 검증 결과가 이후 기간을 대표하지 않을 수 있다. 기존 baseline.json에서 연도별 사건 비율을 이미 확인했으므로 완전한 블라인드 시험이라고 부르지 않는다. 이제부터 최종 평가 결과로 변수·모델을 반복 선택하지 않는다.

## 입력과 제외

입력: category(업태), gu(구군), ld에서 얻은 개업 월. 범주 전처리는 학습 자료에만 맞추고 새 범주는 안전하게 처리한다.

제외: 폐업일·현재 상태·영업기간·현재 생존 여부, uid·건물 키·상호, 전체 기간 자리 통계와 공실/전이 요약, 최신 인구·교통 자료. 식별자·미래 결과·시점 불명확 자료를 입력에 넣지 않는다. 주소 추출의 구군 역시 현재 스냅샷 기반이라는 한계는 유지한다.

## 기준선과 후보

1. 학습 자료의 사건 비율을 모든 대상에 동일하게 적용하는 상수 확률 기준선.
2. 범주 원핫 인코딩 + L2 로지스틱 회귀(C=1, class_weight=None)를 첫 후보로 사용. 전처리·계수는 학습 구간만 사용하고, 첫 평가에서 별도 재학습은 하지 않는다.

기존 KM 요약은 재현 확인용이며 전체기간 KM을 시간 분리 예측의 기준선으로 사용하지 않는다. 모델 학습은 아직 미실행이며 설치·버전과 실제 설정은 실행 시 기록한다.

평가: Brier score·log loss(확률 오차), ROC-AUC·average precision(순위 구분), 확률 구간별 실제 사건 비율과 구군별 표본·오차를 함께 본다. 임의의 정확도만으로 채택하지 않는다. 사건이 없거나 작은 집단은 지표 해석을 제한한다. 보정 모델 추가 여부는 검증 자료로만 판단한다.

## 자리 중복과 추가 평가

검증 5,681건 중 학습과 uid 중복 2,293건, 건물 중복 2,717건이다. 최종 평가 5,837건 중 학습과 uid 중복 2,318건, 건물 중복 2,648건이다. 이 값은 인허가 행 수이며 건물 수가 아니다.

주소를 입력에 넣지 않아도 같은 건물의 관측은 독립적이지 않을 수 있다. 최종 평가에서는 전체와 별도로 학습·검증 어디에도 없는 건물의 기록 2,715건을 보고한다. 이 비교는 별도 모집단이므로 성능 차이를 주소 누출의 크기로 단정하지 않는다. 건물 키 자체도 전체 스냅샷에서 생성되었으므로 완전한 시점별 분리를 보증하지 않는다.

## 검증 및 다음 단계

입력 해시 일치, 분할 중복 없음, 365일 정답 관측 완료 후 다음 기간 시작, 최종 평가 추적 완료를 검사했다. 수치와 변수 목록은 protocol.json에 저장했다. 재현: `python scripts/plan_d03.py`.

다음은 고정한 기준선과 로지스틱 회귀를 실행하고 검증 결과를 비교하는 단계다. 운영 서비스·DB·원본은 변경하지 않았다.
