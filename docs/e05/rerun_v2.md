# 실험 ① 재실행(v2): 비점포 업태 제외 후 결과 (2026-11-09)

## 왜 다시 돌렸나
42종 서비스 확장을 점검하다가 **건강기능식품일반판매업 20,850건 중 11,273건이 점포가 아닌 판매 방식**(전자상거래 6,285, 방문판매 2,138, 통신판매 1,749, 다단계판매 1,004, 도매·전화권유 97)으로 등록된 것을 확인했다. 서비스 전제(점포형 업종)와 맞지 않으며, 첫 실행(v1)에서 사례 1,891건의 직전 가게와 "채워짐" 281건(평가 구간 2단계 50건)의 다음 가게가 이런 등록이었다.

- 조치: `service/pipeline/build.py` 정제 단계에서 `config.NON_STOREFRONT_CATEGORIES` 업태를 제외(실제 제외 11,278건, 테스트 추가) → 42종 재가공 → 실험 파이프라인 전체를 같은 코드·같은 설정·같은 판정 기준으로 재실행.
- **평가 구간을 두 번째로 연 것**이다. 모델·변수·설정값은 바꾸지 않았고 데이터 정의 오류만 고쳤다. v1 결과는 지우지 않고 아래에 함께 둔다(스크래치 `vf_v1/`).
- 입력 고정: 새 빌드 SHA-256 → `results/input_sha256.txt`. 누수 테스트(시점 기준·상가정보) 재실행 모두 통과.

## 결론
- 결론은 v1과 같다: 시점 기준 모델(M3·M1 + 상가정보)이 평가 구간에서 현재 방식(B1)을 순서·확률 모두에서 넘고, 상가정보는 약 +0.01 보탠다. 최종 기록 변수를 쓰면 0.95로 부풀려진다.
- 비점포 등록을 빼자 모델 성능은 조금 올랐다(검증 +0.03, 평가 +0.003~0.010). **이후 서비스·논문 수치는 v2를 쓴다.**
