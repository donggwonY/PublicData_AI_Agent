# 행정동 보정 후보 적용·보류 기준

2026-10-30. D-04 로컬 점검에 따른 제안 기준이다. 운영 반영이나 팀의 최종 승인 기록이 아니다.

## 현재 처리 기준

| 대상 | 건수 | 현재 처리 | 다음 확인 |
| --- | ---: | --- | --- |
| 기존 연결 | 222,850 | 그대로 보존 | 연결 성공이 경계 정확도를 보장하지는 않음 |
| 같은 구군·현재 행정동명이 보존 주소와 일치 | 2,518 | 별도 검토표에서만 후보 연결 | 독립 주소 근거와 현재 행정동 소속 확인 |
| 추가 후보 중 대표 매핑 혼재 경고 없음 | 136 | 미연결 상태 유지, 검토 후보로 기록 | 주소 위치와 현재 행정동 소속 확인. 경고 없음은 정확성 보장이 아님 |
| 추가 후보 중 대표 매핑 혼재 경고 있음 | 57 | 대표값으로 강제 연결하지 않음 | 해당 주소의 실제 행정동 확인 |
| 그 밖의 미연결 | 297 | 원본 보존, 미확정 유지 | 누락·옛 명칭·오기 등을 근거별로 확인 |

미연결 3,008건 = 2,518 + 136 + 57 + 297. 검토표에서만 2,518건을 연결했으므로 잔여는 490건이다. 136건과 57건은 그 490건의 일부이며 아직 추가 연결하지 않았다.

## 실제 반영 전 충족할 조건

1. 목적을 현재 행정동 맥락 조회로 명시한다. 과거 시점의 소속이나 예측 모델 입력에 사용하려면 해당 시점의 행정경계·유효기간을 따로 확인한다.
2. 동일 구군 안에서 대상 행정동이 하나로 결정되고, 주소 간 충돌이 없어야 한다. 주소 이름 일치에 더해 독립적인 공식 주소 대응이나 유효한 좌표와 해당 기준일 행정경계 등으로 소속을 확인한다. 좌표가 있다는 것만으로 통과시키지 않는다.
3. 원래 gu·dong과 기존 연결은 덮어쓰지 않는다. 인허가 복합키(service, org_code, mgmt_no), 후보 행정동, 연결 방법, 근거 출처·기준일, 검토 상태, 입력 버전을 별도로 보존한다. uid는 자리 키이므로 인허가 고유키로 쓰지 않는다.
4. 반영 전후 행수·복합키·기존 연결 불변·다대일 관계를 검사하고 업종별·구군별 집계 변화를 비교한다. 실패율이 낮아졌다는 이유만으로 공간 정확성이 검증됐다고 판단하지 않는다.
5. 운영 반영은 공유 DB 대상·권한·서비스 버전을 확인하고 기존 운영 절차에 따라 염동권과 조율한다. 현재 검토표는 반영 승인을 대신하지 않는다.

현재는 독립 원본·경계 대조가 완료되지 않아 운영 적용 조건을 충족했다고 선언하지 않는다. 추가 자료 요청은 사용자 요청에 따라 보류 상태로 유지한다.

## 분석에서 미연결을 다루는 방법

행정동이 필요 없는 분석에서는 다른 필수값이 유효하면 포함한다. 행정동별 분석에서는 미연결을 별도 집단으로 표시하거나 목적에 맞게 제외하되, 전체·업종별·구군별 제외 수와 비율을 함께 남긴다. 원본 행을 일괄 삭제하지 않는다. 검토 후보를 포함한 결과는 확정 연결 결과와 섞지 않고 별도의 민감도 비교로 표시한다.

종료 표시 없이 종료일이 있는 108건(축산판매업 105건, PC방 3건)은 별도 상태 검토 대상이다. 상세 영업 상태와 날짜 출처를 확인하기 전 종료 여부를 바꾸거나 삭제하지 않는다. 이 108건은 행정동 미연결 집단과 중복될 수 있으므로 위 표에 더하지 않는다.

## 남은 업무와 완료 증거

- 로컬 연결 진단·날짜 점검·업종 확장 비교·보정 기준 정리: 완료. 아래 보고서와 검증 결과가 근거다.
- 독립 원본·경계 확인: 미완료. 자료 요청 보류에 따라 미확정 항목으로 인계한다.
- 공유 DB 직접 비교: 미완료. 대상·읽기 권한·버전 확인 후 같은 버전의 로컬/DB 행수·키·집계를 대조한 기록이 필요하다.
- E-02 부록 A-4 질문: 과거 DB와 현재 DB를 구분해 답변 초안을 정리할 수 있다. 조회하지 않은 표의 존재나 삭제 가능 여부를 확정하지 않는다.

D-04 전체 완료로 표시하지 않는다. 다음 로컬 작업은 기존 문서에 있는 A-4 질문의 답변 초안과 미확인 사항을 한 번에 정리하는 것이다.
