# 대구 상권 생애주기 AI 에이전트 — 구현 설계

기준: 2026-09-29, 코드 위치 갱신 2026-10-11. 이 문서는 **프로젝트를 처음 접하는 사람**을 위한 설계 기준입니다. `PublicData_AI_Agent`는 팀 지침·작업 기록과 서비스 코드를 함께 두는 저장소입니다. 서비스 코드는 2026-10-11에 [daegu_lifecycle_agent](https://github.com/donggwonY/daegu_lifecycle_agent) `main`(1932844)에서 `service/` 폴더로 옮겨 왔습니다. 아래에서 "참고 구현"은 이 `service/` 코드의 현재 상태를 가리키며, 파일 경로는 `service/` 기준입니다. 아래의 Supabase 이전과 새 분석 기능은 목표이며 **구현 완료를 뜻하지 않습니다**. 참고 구현의 파일과 동작은 바뀔 수 있으므로 작업 전에 실제 코드를 다시 확인합니다.

## 처음 작업할 때 확인할 곳

1. 이 저장소의 [멘티 플레이북](MENTEE_PLAYBOOK.md)과 [작업판](WORKBOARD.md)에서 담당 작업을 고릅니다. 앱 코드는 이 저장소의 `service/`에 있으며 실행 방법은 `service/README.md`를 확인합니다. 원래 저장소는 과거 이력 확인용으로만 봅니다.
2. 참고 구현의 `app.py`는 Streamlit 화면과 상담 UI, `pipeline/build.py`와 `pipeline/external.py`는 데이터 가공 배치, `data/processed/`는 가공 결과, `core/tools.py`는 데이터를 조회·계산해 결과를 돌려주는 Python 함수 모음입니다. `agent.py`는 AI 상담에서 이 함수를 호출하고, `mcp_server.py`는 같은 함수를 MCP 방식으로 외부 AI 클라이언트에 노출합니다. **MCP는 함수 연결 방식이지 별도의 분석 모델이 아닙니다.**
3. 데이터나 기능을 바꾸기 전에 원천 자료의 출처·이용 조건, 가공 코드, 데이터 기준일(`data/processed/meta.json`), 관련 함수와 테스트를 확인합니다. 원본 CSV가 없다면 기존 Parquet 스냅샷으로 가능한 분석과 원본이 있어야 재현 가능한 배치를 구분합니다. Parquet는 표 데이터를 저장한 파일 형식입니다.

## 제품 목표

대구의 음식점 인허가 이력과 보조 데이터를 이용해 지역·자리의 변화, 점포 생존, 업종 전이 등을 조회하고 창업 판단에 필요한 **근거 있는 설명**을 제공합니다. 발표 시에는 대표 질문의 결과를 재현할 수 있어야 하며, 분석 기준일·지표 정의·한계를 사용자가 확인할 수 있어야 합니다. 추천은 투자·창업 성공 보장이 아닙니다.

## 데이터 이전 원칙

Parquet는 현재의 **가공된 표 파일 형식**이지 별도 DB가 아닙니다. Supabase로 옮길 때 파일을 그대로 DB라고 부르지 말고, 각 파일의 행·열·키·자료형·기준일을 확인해 PostgreSQL 조회 테이블로 매핑합니다. 원본 CSV는 공개 저장소에 올리지 않습니다.

1. 데이터 사전 작성: 출처, 수집일, 갱신 주기, 컬럼 의미, 주소 정규화·중복 제거 규칙, 결측 처리.
2. 조회용 스키마와 인덱스 설계: 참고 구현의 `data/processed/stores.parquet`(점포), `units.parquet`(자리), `transitions.parquet`(자리의 업종 전이), `area_year.parquet`(지역·연도 집계) 등에서 필요한 조회를 추려 시작합니다. 파일 이름을 그대로 DB 스키마로 복사하지 말고 키와 관계를 검증합니다. 원본·배치 결과의 버전과 데이터 기준일(`reference_date`)을 보존합니다.
3. 배치 파이프라인은 유지: 무거운 통계(생존율·공실 후보·상권 단계)는 배치에서 계산하고 상담 중에는 검증된 결과를 조회합니다. 갱신 실패 시 이전 정상 스냅샷을 유지합니다.
4. 이전 전후 검증: 행 수, 고유 자리 수, 핵심 지표, 대표 주소 이력, 도구 응답을 비교합니다. 숫자가 달라지면 원인을 기록하고 발표 자료를 갱신합니다.
5. DB 권한: 앱에 필요한 최소 권한만 부여하고 비밀키를 브라우저로 보내지 않습니다. 사용자 데이터가 생기면 사용자별 접근 통제를 설계합니다.

## AI 상담 호출 원칙

`google-genai` SDK는 Streamlit **서버 측**에서 Gemini API를 호출합니다. Google AI Studio는 키·프로젝트·호출 제한을 관리하는 곳이며 상담 UI 자체가 아닙니다. 운영자가 키를 제공하면 방문자들의 호출이 같은 Google 프로젝트 할당량을 사용합니다. 무료 등급 한도는 모델·프로젝트별로 달라 [AI Studio Rate limits](https://aistudio.google.com/rate-limit)에서 실제 값을 확인합니다. 무료 등급의 입력 데이터 처리 조건은 [Gemini 요금 문서](https://ai.google.dev/gemini-api/docs/pricing)를 확인합니다.

LLM에는 임의 SQL이나 무제한 코드 실행 권한을 주지 않습니다. 상담에서 호출할 **읽기 전용 분석 함수**를 질문별로 정의합니다. 예를 들어 "수성구 카페의 생존율"에는 지역명과 업종명을 허용된 값으로 정규화하고, 기간 범위와 최대 반환 건수를 제한합니다. 같은 동명이 여러 구에 있거나 표본이 너무 적으면 임의로 추측하지 말고 추가 정보를 묻거나 계산 불가 이유를 반환합니다. 함수 결과에는 계산값뿐 아니라 표본 수, 지표 정의, 관측 기간, 데이터 기준일, 결측·제외 사유를 포함합니다. 참고 구현의 함수 형식은 `core/tools.py`에서 확인하되, **함수 개수나 현재 구현이 그대로 유지된다고 가정하지 않습니다.**

AI 답변이 함수 결과에 없는 수치를 만들어내면 실패로 판단합니다. 대표 질문별로 함수 반환값과 최종 문장의 숫자가 일치하는지 검사합니다. 응답 지연·모델 호출 횟수·429 오류를 기록하고 운영자 키에 사용자별·전체 호출 제한을 둡니다. 로컬 ChatGPT/Codex 구독 로그인은 공개 웹앱의 공용 호출 수단으로 사용하지 않습니다.

## 데이터 분석과 ML 실험 원칙

참고 구현의 기술통계와 규칙 기반 계산을 학습된 ML 모델이라고 부르지 않습니다. 김세은은 데이터 품질·생존 코호트와 결과 정의를, 김선경은 보조 데이터 결합·지역/시간 분석과 AI 도구 평가를 중심으로 하되, **두 학생 모두 탐색 분석·기준선·모델 후보·오류 분석에 참여**합니다. 염동권은 검증된 결과의 배치/조회/표시와 운영을 맡습니다. 상세한 질문과 학생별 선택지는 [멘티 플레이북](MENTEE_PLAYBOOK.md)에 둡니다.

예측 문제는 학생들이 먼저 사용 목적과 관측 단위를 제안합니다. 가능한 출발점은 점포/자리의 일정 기간 사건 분석, 지역별 다음 기간 개폐업 수, 보조 데이터에 따른 상권 유형 탐색입니다. 실제로 예측 가능한 결과인지와 데이터 품질을 확인한 뒤 하나를 좁힙니다. 미래 데이터를 과거 특징에 섞지 않고 시간 순서·반복 장소 누출을 점검합니다. 간단한 기준선과 비교해 이득이 없으면 서비스 도입을 보류하고 그 이유를 발표합니다. 폐업 신고를 사업 실패, 신규 인허가 부재를 실제 공실로 단정하지 않습니다.

## 발표 전에 충족할 조건

- 대표 질문 3~5개의 기대 수치와 설명을 고정해 회귀 확인합니다. 질문에는 지역 비교, 특정 자리 이력, 업종 생존 등을 포함합니다.
- 최신 데이터 기준일과 정의를 화면에 표시하고, 결과의 한계(인허가 자료가 실제 임대 공실을 직접 측정하지 않음 등)를 명시합니다.
- 배포 주소에서 새 방문자 기준으로 상담·대시보드·자리 조회를 확인하고, API 한도 도달 시 안내가 나오는지 확인합니다.
- 공개 배포 전에 비용·할당량·비밀값·오류 로그를 점검합니다. 발표 당일에는 앱을 미리 깨우고 로컬 실행본을 예비로 준비합니다.

## 코드 위치와 배포 (2026-10-11 결정)

- **코드 위치**: 서비스 코드를 이 저장소의 `service/` 폴더로 옮겼습니다. 원래 저장소 `main`(1932844)과 파일 내용이 같은 상태로 가져왔고(Git 트리 해시 일치), 과거 커밋 이력은 가져오지 않았습니다. 근거와 검토한 선택지는 [E-01 기록](E01_demo_reproduction.md) 9절에 있습니다.
- **하위 폴더로 둔 이유**: 루트의 `config/`·`tests/`·`scripts/`와 이름이 겹치지 않고, 파일 내용이 그대로라 D-01·D-02의 입력 해시 검증이 유지됩니다.
- **브랜치**: 멘티는 `main`에 직접 푸시합니다. 공개 앱은 `deploy` 브랜치에서 배포해 문서·실험 푸시가 서비스에 영향을 주지 않게 합니다. `deploy` 갱신은 염동권이 검증 후 수행합니다([작업 흐름](TEAM_WORKFLOW.md)).
- **배포 전환**: Streamlit Community Cloud 앱을 `donggwonY/PublicData_AI_Agent` · `deploy` · `service/app.py` · Python 3.12로 새로 만들어야 합니다. 전환을 확인하기 전까지 기존 앱(원래 저장소 `main`)이 공개 서비스입니다. 전환 상태는 E-01 기록에 남깁니다.
