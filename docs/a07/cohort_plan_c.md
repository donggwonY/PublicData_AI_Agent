# A-07 추가 실험 C안: 1세 단위 나이 이동 (계획, 2026-11-18 고정, 실행 전)

담당 염동권(에이전트 수행) · [B안 결과](cohort_results.md)의 후속. B안 파일과 결과는 바꾸지 않는다.

## 왜 하는가
B안은 10세 구간 안에서 나이가 고르게 퍼져 있다고 보고 해마다 1/10씩 다음 구간으로 넘겼다. 70대·80대는 이 가정으로 통과하지 못했다. 베이비붐 세대(1955~1963년생)가 70대로 들어오는 시기에는 69세 인원이 60대 평균보다 많아 1/10 가정이 맞지 않는 것으로 보인다. 1세 단위 자료로 **경계 나이의 실제 인원**을 넘기면 나아지는지 확인한다.

## 입력
- 행안부 [연령별 인구현황](https://jumin.mois.go.kr/ageStatMonth.do) 전체읍면동 CSV, 등록구분 거주자, **1세 단위**(0~99세, 100세 이상), 2016-01~2026-10. 성별 구분 없이 합계만 받는다.
- 3개월씩 요청하고 대구 행만 Git 제외 경로 `data/raw/a07_cohort/src_1y/`에 저장한다. 요청 양식과 전국 응답 SHA-256은 같은 폴더 `sources.json`에 남긴다.
- **사전 점검**: 모든 월·지역에서 1세 인원을 10세 구간으로 합친 값이 B안 입력(10세 구간 자료)과 같아야 진행한다. B안의 행 수와 A-07 재현 점검도 그대로 통과해야 한다.

## 새 방법
연령대 b의 가장 높은 나이 top(b)(예: 70대 → 79세), 바로 아래 연령대 b−1의 가장 높은 나이 top(b−1)(예: 69세).

| 이름 | 1년 뒤 인구 예측 |
|---|---|
| **C2 정확한 나이 이동** | S_b(t) = P_b(t) − P_top(b)(t) + P_top(b−1)(t). 지난 1년 변화율 r = P_b(t) / S_b(t−12), 작은 동 보정(k)은 C1과 같은 방식. 예측 = S_b(t) × r̂ |
| **B2 C2 + 보정 릿지** | 목표 = 실제 − C2 예측. 입력: B의 입력 + 경계 나이 인원 P_top(b)(t), P_top(b−1)(t)와 각각의 12개월 변화. 예측 = C2 + 보정 |

- 0~9세: S = P_{0~9}(t) − P_9(t)(출생 유입은 r에 담음). 100세 이상: S = P_{100+}(t) + P_99(t). 전체 인구: 나이 이동이 없으므로 C2 = C1, B2 = B로 둔다.
- k ∈ {0, 100, 1000, ∞}, alpha ∈ {1, 10, 100}. B안과 같은 후보다.

## 선택과 판정 (B안과 같은 규칙)
- 평가 틀(구간, 시점 이동 학습, 반올림·0 자르기)과 지표는 B안과 같다.
- 연령대마다 **개발 구간**에서 C2의 k, B2의 alpha를 고르고, {R0, R1, C1, B, C2, B2} 중 개발 구간 평균 절대오차가 가장 작은 방법을 표시 후보로 정한다.
- 최근 평가 구간에서 표시 후보가 R0보다 오차가 작고, 행정동 단위 블록 부트스트랩(1,000회, seed 0) 95% 개선 구간 상한이 0보다 작으면 표시한다.

## 알고 있는 한계
- 최근 평가 구간은 A-07에서 여러 번, B안에서 한 번 더 사용했다. B안에서 70대·80대의 최근 평가 결과를 본 뒤 C안을 정했으므로, 이 판정은 독립 시험이 아니다. 설정 선택에는 최근 평가 결과를 쓰지 않는다. 표시하게 되더라도 2027-10 공표 인구로 다시 검증해야 한다고 적는다.
- 사망률 표(통계청 생명표)는 쓰지 않는다. 사망은 동별·구별 변화율 r에 함께 담긴다.

## 하지 않는 것
B안 결과 덮어쓰기, 결과를 본 뒤 후보 설정 추가, 성별 분리, DB 적재, 앱 반영.
