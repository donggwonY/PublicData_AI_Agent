# A-07 추가 실험: 30대·0~9세 이사 신호 (계획, 2026-11-18 고정, 실행 전)

담당 염동권(에이전트 수행) · [C안 결과](cohort_results_c.md)의 후속. 기존 결과·파일은 바꾸지 않는다.

## 왜 하는가
C안 기준 30대는 오차 79.6명으로, "변화 없음"(87.9명)보다 9%만 낫고 증감 방향 적중률이 기준선보다 낮다(62.9% 대 71.4%). 30대는 구매력이 큰 창업 핵심 고객층이라 1년 뒤 증감 정보가 중요하다. 30대 인구는 나이 듦보다 이사(결혼·직장·아파트 입주)로 움직이는데 지금 입력에 이사 신호가 없다. 0~9세는 부모와 함께 이사하므로 같은 신호와 출생 유입 신호로 함께 개선을 시도한다.

## 대상
30~39세(`age_30_39`), 0~9세(`age_00_09`). 다른 집단은 다루지 않는다.

## 입력
- B안·C안과 같은 행안부 거주자 자료(10세 구간 `src/`, 1세 단위 `src_1y/`). 사전 점검(행 수, A-07 재현, 1세 합계)도 같다.
- 2단계(별도 실행 전 확인): 국토부 건축인허가 정보(공공데이터포털)의 착공·사용승인·멸실 세대수. 1단계 결과를 본 뒤 진행 여부를 정하며, 진행 시 요청 범위와 횟수를 먼저 알린다.

## 1단계 새 변수 (모두 기준월 t 시점에 알 수 있는 값)
| 묶음 | 변수 |
|---|---|
| 가족 이사 | 같은 동의 0~9세·30대·40대 12개월 변화, 0~9세 ÷ 30대 비율 |
| 나이 구성 | 30대 안의 30~34세 비중, 0세 인원과 12개월 변화 |
| 구 안의 흐름 | 같은 구 다른 동들의 해당 연령대 12개월 변화율(자기 동 제외) |

## 비교하는 방법
| 이름 | 내용 |
|---|---|
| R0, R1, C2, B2 | 기존(기준선, A-07 릿지, 1세 이동, 1세 이동+보정 릿지) |
| C3 (0~9세만) | 출생 유입을 직접 넣은 나이 이동: S = P_{0~9}(t) − P_9(t) + P_0(t). 내년에 0세로 들어올 인원을 최근 1년 출생(현재 0세)으로 본다. 변화율·작은 동 보정은 C2와 같다 |
| B3 | 기본값(30대 C2, 0~9세는 C2·C3 중 새 개발 구간에서 나은 것) + 보정 릿지. 입력 = B2 입력 + 1단계 새 변수 |
| H3 | B3와 같은 기본값·입력, 보정 모델만 HistGradientBoosting(max_iter 200, max_leaf_nodes 15, min_samples_leaf 30, learning_rate 0.05, random_state 7, 고정) |

k ∈ {0, 100, 1000, ∞}, alpha ∈ {1, 10, 100}. H3 설정은 고정이며 고르지 않는다.

## 구간 (기존 평가 구간 재사용을 피한다)
| 용도 | 기준월 | 쓰는 방법 |
|---|---|---|
| **새 개발 구간** | 2019-11~2022-10 | k·alpha·기본값·방법 선택 (평가에 쓴 적 없는 구간) |
| 참고 구간 | 2023-11~2025-10 | 이미 여러 번 본 구간. 선택에 쓰지 않고 보고만 |
| **최종 판정 구간** | 2025-11~ | 정답이 2026-12부터 한 달씩 공표되는 새 구간 |

학습은 기존과 같이 기준월 ≤ m−12 행만 쓴다(시점 이동).

## 판정
- 선택: 연령대마다 새 개발 구간 인구 평균 절대오차가 가장 작은 방법.
- **잠정 반영 기준**(발표 전 앱 반영 여부): 선택한 방법이 참고 구간에서 ① R1·R0보다 오차가 작고 ② 증감 방향 적중률이 R0 이상이며 ③ R0 대비 개선의 동 단위 부트스트랩(1,000회, seed 0) 95% 구간 상한이 0 미만. 참고 구간은 재사용 구간이므로 "잠정"으로 표시한다.
- **확정 기준**: 최종 판정 구간에서 기준월 6개월(2025-11~2026-04) 정답이 쌓이면 같은 ①~③을 다시 본다.
- 통과하지 못하면 지금 방법(30대·0~9세 R1)을 유지하고, 30대·0~9세의 증감 방향 문구는 쓰지 않는다.

## 2단계 추가 계획 (2026-11-18 고정, 1단계 결과 확인 후·2단계 실행 전)
1단계 새 변수는 도움이 되지 않았다([결과](age30_results.md)). 2단계는 앞으로의 입주 물량을 알려 주는 건축인허가 자료만 더한다.

- **입력**: 국토교통부 건축HUB 건축인허가 기본개요(`ArchPmsHubService/getApBasisOulnInfo`), 대구 법정동 전체. 법정동 코드는 `docs/d03/daegu_legal_codes.json`(code.go.kr). 원본은 Git 제외 `data/raw/a07_cohort/permits/`.
- **철거·멸실은 빼다**: 철거멸실관리대장 기능 이름을 활용 가이드 파일 없이 확인하지 못했다. 계획의 멸실 세대수 변수는 이번에 쓰지 않는다.
- **대상 기록**: 건축 구분 '신축'이고 세대수(`hhldCnt`)가 1 이상인 기록(주로 공동주택).
- **법정동 → 행정동**: 서비스의 `legal_admin_map`(법정동 안 점포가 어느 행정동에 있는지 비율)로 세대수를 나눈다. 대응이 없는 법정동은 같은 이름의 행정동이 있으면 그쪽으로, 없으면 쓰지 않고 그 세대수를 기록한다.
- **변수**(기준월 t, 행정동별, 모두 t 시점에 알 수 있는 값):
  1. 최근 입주: 사용승인일이 (t−12개월, t]인 세대수
  2. 곧 입주: 실제 착공일이 (t−36개월, t−12개월]이고 t까지 사용승인되지 않은 세대수
  3. 위 두 값을 그 동 총인구 1,000명당으로 나눈 값
- **방법**: B4 = 1단계와 같은 기본값(30대 C2, 0~9세는 1단계에서 정한 기본값) + 보정 릿지(입력 = B2 입력 + 위 변수). H4 = 같은 입력의 HistGradientBoosting(1단계 H3와 같은 고정 설정). alpha 후보도 같다.
- **선택·판정**: 1단계와 같다(새 개발 구간에서 선택, 참고 구간에서 잠정 판정 ①~③, 최종 판정 구간에서 확정).
- **알려진 한계**: 인허가 자료는 현재 시점 목록이라, 과거에 취소된 허가가 빠져 있을 수 있다. 착공 뒤 사용승인까지 걸리는 기간은 단지마다 다르다.

## 하지 않는 것
기존 결과 덮어쓰기, 결과를 본 뒤 변수·설정 추가, 참고 구간으로 설정 고르기, DB 적재, 앱 반영.
