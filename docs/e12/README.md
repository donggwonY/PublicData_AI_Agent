# E-12 동이 비어 있는 인허가 — 원인 확인·수정

담당 염동권 · 2026-11-20 · [작업판](../WORKBOARD.md) E-12 · 계기: [E-04](../e04/README.md) 데이터 점검의 행정동 미연결 5.08%

1~3절은 코드를 바꾸기 전 1단계 기록이고, 4절이 수정(2단계)이다. 대상은 저장소 가공 데이터(`service/data/processed`, 기준일 2026-11-06, DB v10과 같은 배치)다. 수치는 Python 계산 결과다.

## 1. 원인: 원본 주소의 번지가 가려져 있다

`stores.dong`이 빈 인허가는 11,646건(전체 286,896건의 4.1%)이다. 영업 중인 것이 3,505건이다. 주소 형식으로 나누면 다음과 같다.

| 형식 | 건수 | 영업 중 | 예 |
| --- | ---: | ---: | --- |
| 번지가 `*`로 가려짐 | 11,335 | 3,482 | `대구광역시 남구 대명동 ****-*` |
| 그 밖(동 이름 붙여 쓰기, 번지 없음 등) | 270 | 23 | `대구광역시 남구 대명04동3048-34` |
| 구·군 이름 없음 | 41 | 0 | `대구광역시 다사읍 세천로 80` |

- 가려진 주소는 모두 42종 확장 때 들어온 업종이다. 건강기능식품일반판매업 9,577건, 동물미용업 835건, 동물위탁관리업 504건, 동물판매업 419건이다.
- 원본이 번지를 가린 이유는 확인하지 않았다(개인 사업자 주소 보호로 추정).
- 주소 규칙(`core/address.py` `parse_jibun`·`parse_road`)은 번지가 숫자여야 맞는다. 그래서 동 이름이 주소에 그대로 있는데도 동을 읽지 못한다.

## 2. 더 큰 문제: 가려진 주소가 가짜 '자리'를 만든다

- 주소를 못 읽으면 자리 키(`uid`)가 원본 문자열이 된다. 같은 동에서 번지가 가려진 서로 다른 가게들이 **한 자리로 합쳐진다.**
- 이렇게 생긴 가짜 자리는 3,580곳, 인허가 10,768건이다(`units`의 3.7%).
  - 가장 큰 것: `대구광역시 남구 대명동 ****-*` 한 자리에 129건, 동시 영업 최대 48곳.
- 서비스에 보이는 영향:
  - **빈 자리 목록에 나온다.** 구별 빈 자리 목록 첫 20곳 중 중구 2곳, 수성구 2곳, 남구 1곳, 달성군 1곳이 가짜 자리다(`find_vacant_units`, 2026-11-20 확인).
  - 공실 재입점 점수(E-03)와 다음 업종 확률(E-09) 표에 220곳씩 들어 있다.
  - 자리 이력 조회도 된다. 가려진 주소로 조회하면 "영업중 46개"처럼 서로 다른 가게가 한 자리로 나온다.
  - 위험 자리 목록에는 나오지 않았다(단일 점포 자리만 고르므로).
- 동이 비어 있으니 동 단위 집계와 동네 카드(인구·비슷한 동네)에서도 빠진다.

## 3. 고칠 방향 (제안)

**① 동 읽기**: 번지가 가려져도 구·동은 읽게 한다.
- 시험 계산: 동 결측 11,646 → 309건, 행정동 미연결 5.08% → 1.49%(15업종 때 1.33%와 비슷).

**② 가짜 자리 없애기**: 번지가 가려진 인허가는 자리를 특정할 수 없다.
- 인허가 수, 개업·폐업 수, 생존 같은 **가게 단위 집계에는 남긴다.** 동을 읽게 되면 동 단위 집계에도 들어간다.
- **자리 단위 결과에서는 뺀다.** 대상은 `units`, 전이, 공실 후보와 공실률, 빈 자리 목록, 자리 이력, 공실 점수와 다음 업종 표다.
- 데이터 계약을 바꾼다. `stores`에 "번지 가림" 표시를 두고, 이 행은 `units` 연결 검사에서 뺀다.

**운영 영향**
- 배치 재생성, DB 새 버전 적재, 전환, 배포가 필요하다.
- 공실 재입점 점수(E-03)와 다음 업종 확률(E-09) 표는 오프라인 배치 결과다. 가짜 자리 220곳은 다시 학습하지 않고 표에서 빼기만 하면 된다.
- 모델 학습 자료에 가짜 자리가 섞였던 영향은 따로 평가하지 않는다.

## 4. 수정 (2단계, 2026-11-20)

위 ①·② 방향으로 고쳤다. 같은 원본(기준일 2026-11-06)으로 배치를 다시 만들어 저장소 가공 데이터에 반영했다. DB 적재·전환·배포는 아직 하지 않았다.

**코드**
- `core/address.py` `parse_masked`: 번지가 `*`인 지번·도로명 주소에서 구·읍면·동을 읽는다. 자리 키는 만들지 않는다.
  - 지번형은 동이 `동·가·리`로 끝날 때만 받는다. 처음에는 `로`도 받아 도로명(`진천로`)을 동으로 읽은 40건이 있었고, 테스트로 찾아 고쳤다.
  - 도로명형은 괄호 안 법정동이 있을 때만 동을 채운다.
- `pipeline/build.py`:
  - `stores.addr_masked`(새 열)를 만든다.
  - 겸업 묶기까지는 원래 문자열로 하고, 그 뒤 `uid`·`building_key`를 비운다.
  - `units`는 자리 키가 있는 가게로만 만든다. 그래서 전이·공실·자리 이력에서 빠진다.
  - 오프라인 결과 표(`vacancy_scores`·`next_tenant_scores`)는 새 `units`에 없는 자리 행을 뺀다. 다시 학습하지 않는다.
- `core/tools.py`: 상호명으로 자리를 찾을 때 빈 자리 키를 건너뛴다.
- `pipeline/check_data.py`:
  - `units`·`stores`·전이·결과 표에 `*`가 든 자리 키가 있으면 FAIL이다.
  - `stores.uid`가 빈 행은 `addr_masked`일 때만 허용한다.
  - 행정동 미연결 경고선을 6.1%에서 2.5%로 낮췄다.
- 테스트: `tests/test_masked_address.py` 7개.

- 인허가 286,896건·영업 중 84,444건은 그대로다.
- 번지 가림 인허가는 11,337건이다. 1단계 분류보다 2건 많은데, 지번에는 번지가 없고 도로명만 가려진 경우다.
- **진짜 자리 92,279곳은 모든 열이 이전과 같다.** 가짜 자리만 빠졌다.
- 단기 행사 표시가 138곳 줄었다. 가짜 자리가 다점포로 잡혀 짧게 문 닫은 가게가 행사로 빠졌던 것이 돌아왔다.
- 구별 공실률이 0.0~0.4%p 바뀌었다(예: 수성구 9.3→8.9%, 중구 12.8→12.5%).
- 동 단위 집계에 동물·건강기능식품 가게가 들어가 동 수가 늘었다.

**검증**
- `check_data` OK 30 · WARN 0 · FAIL 0. 이전 데이터는 가짜 자리 검사에서 FAIL 5건이었다.

- 구별 빈 자리 목록에 가려진 주소 0곳(이전 6곳).

**남은 것**
- 동이 비어 있는 330건: 동 이름 붙여 쓰기(`대명04동3048-34`), 구 이름 없음 등이다. 규칙을 더 넓히면 오인식 위험이 있어 두었다.
- 가려지지 않은 인허가 중 동이 `로`로 끝나는 335건이 있다. 지번 칸에 도로명이 들어간 경우로 보이며, 따로 확인할 후보다.
- E-05 패널·모델 학습 자료에는 가짜 자리가 섞여 있었다. 영향은 평가하지 않았다.
- 번지 가림 가게만 이름이 맞을 때는 지금 "찾지 못함"으로 나온다. 이유를 안내하는 개선은 후속 후보다.

## 6. 후속 정리 (2026-11-20, 저장소 반영·운영 반영 전)

**① 번지 가림 가게만 이름이 맞을 때 이유 안내** (`core/tools.py` `_masked_name_note`)
- 주소 찾기(`normalize_address`)와 자리 이력(`get_unit_history`)에서 결과가 없을 때 쓴다. 상호가 번지 가림 인허가에만 맞으면 "찾지 못함" 대신 이유를 알려 준다.
- 안내 내용: 번지가 가려져 자리를 특정할 수 없다는 것, 건수와 주요 동, 가게 수·개폐업 집계에만 들어간다는 것.
- 예: '신선바이오테크' → 38건, 남구 대명동·서구 평리동·달서구 상인동.

**② 동이 비어 있던 330건** (`core/address.py` `parse_area_loose`, `pipeline/build.py`)
- 정규 형식이 아닌 주소에서 구·동만 읽는다. 다룬 형식:
  - 번지와 붙여 쓴 주소: `태전동496-12`
  - 행정동식 번호: `대명06동` → 대명동
  - 구와 동을 붙여 쓴 주소: `동구신암1동`
  - 구가 빠진 주소: `대구광역시 신서동`, `대구광역시 다사읍`
- 오인식을 막는 조건: 정규 형식 주소에서 20건 이상 나온 (구, 동)일 때만 받는다. 구가 빠지면 그 동이 한 구에만 있을 때만 구를 채운다.
  - 처음에는 건수 조건이 없어 `팔공로53길 10 (…상가101호)`를 북구 '상가'동으로 읽었다. 기존 오기 1건이 기준 목록에 들어 있었기 때문이다.
- 번지 가림 지번형이 법정동 `남성로`·`시장북로`도 받도록 했다.
- 결과: 동 결측 330 → 30건. 남은 30건은 도로명만 있고 괄호 법정동이 없는 주소, 구 없는 도로명 등이다.

**③ 동이 '로'로 끝나는 335건**
- 325건은 실제 법정동 `남성로`(254)·`시장북로`(71)다(중구). 문제가 아니다.
- 10건은 지번 칸에 도로명이 들어간 경우다(`달서구 대명천로 12 (성당동)`). 괄호 안 법정동으로 동만 바꿨다.
- 처음에는 지번 규칙에서 이런 주소를 빼려 했다. 그러면 도로명→지번 매핑의 동률 처리가 흔들려 무관한 자리 키 205개가 바뀌었다.
  - 자리 키는 E-09 1년 뒤 검증 고정본이 쓰므로, 키는 그대로 두고 동만 고치는 방식으로 바꿨다.

**결과 (같은 원본 2026-11-06으로 재생성, DB v11 대비)**

## 7. 번지 가림의 성격과 '…가' 숫자 가림 (2026-11-20)

**가림은 업종 단위다**
- 원본(`service/data/raw`)에서 번지가 가려진 업종은 4개뿐이다. 건강기능식품일반판매업, 동물미용업, 동물위탁관리업, 동물판매업이다.
- 이 4개 업종은 개업 연도, 영업 상태와 관계없이 **100%** 가려져 있다. 나머지 38개 업종은 0%다.
- 가려진 항목: 지번·도로명의 번지, 층·호, 그리고 법정동 '…N가'의 숫자(예: `태평로*가`).
- 가려지지 않은 항목: 상호, 좌표(EPSG:5174), 구·동 이름.
- 가린 이유는 공식 문서로 확인하지 못했다. 지방행정 인허가데이터(localdata.go.kr) 제공 기준을 찾아봤지만 해당 설명은 없었다.
  - 추정: 이 업종들은 개인이 집에서 영업 신고하는 경우가 많아(온라인 판매, 반려동물 미용·위탁 등) 제공기관이 업종 단위로 상세 주소를 가린 것으로 보인다. 확인되지 않은 추정이다.

**'…가' 숫자 가림 처리** (`pipeline/build.py` `resolve_masked_ga`)
- E-12 수정 뒤에도 동 이름이 '수성동*가'처럼 남은 인허가가 1,048건 있었다. **DB v11(공개 중)과 v12에도 들어 있다.**
  - 동 단위 표에 가짜 동이 생겼다: 사이클 14행, 연도 집계 241행, 생존 7행.
- 좌표는 가려지지 않았으므로, 같은 구·같은 이름 계열(수성동1가~4가 등)의 정상 주소 가게 중 가장 가까운 가게의 동을 쓴다.
  - 1,015건을 채웠다. 좌표가 없는 33건은 동을 비운다.
- `check_data`: 동 이름에 `*`가 남으면 FAIL이다(6개 표).
- 결과: 동 결측 30 → 63건(가린 이름 대신 빈 값), 행정동 미연결 1.39 → 1.04%. 동 단위 표의 가짜 동은 0이다(사이클 359→345행, 연도 집계 7,181→6,942행, 생존 892→885행).
- 자리 키·구·단기 행사 변경 0. `check_data` OK 36·FAIL 0, 테스트 125개·smoke 통과.
- 운영: v12는 이 수정 전 데이터라 전환하지 않는다. 새 버전으로 다시 적재한다.
