# A-10 83개 업종 앱 연동

이번 연동 파일은 **`docs/a10/industry_comparison_app_83.csv`**다. 2026년 9월 대구 읍·면·동 152곳 × 83개 업종인 12,616행을 담았다. [두 후보지 비교 시안](cafe_comparison_preview.html)에서 업종과 동네 두 곳을 직접 선택할 수 있다.

## 업종별 추정 방식

[83개 업종 검증표](expanded_industry_validation.csv)의 `active_method`가 이번 파일에 적용한 방식이다.

| 값 | 설명 | 적용 |
| --- | --- | --- |
| `poisson_context` | 동네 인구·연령 분포·다른 업종 점포 구성 | 61개 업종 |
| `nearby_scale` | 기존 입력에 가까운 세 동네의 인구·기타 점포 규모 추가 | 10개 업종 |
| `nearby_industries` | 주변 규모와 함께 이웃의 업종 구성 추가 | 12개 업종 |

주변 정보를 추가한 22개는 세 시점 모두 기존 모델보다 평균 오차가 작았다. 기존 58개와 6월 확인에서 악화된 3개는 기존 방식을 쓴다. `selected_method`는 처음 두 시점으로 고른 후보이며, 6월에 개선을 확인하지 못한 경우 `active_method`와 다를 수 있다.

83개는 최초 247개 업종 중 두 시점 모두 기존 비교 기준을 충족한 범위다. 나머지 164개는 이번 연동 범위에 포함하지 않았다. 집단 평균 오차 개선이 개별 지역의 정확성을 보장하지는 않는다. 분기 사이에는 같은 점포가 겹칠 수 있다.

## 조회와 표시

CSV 필드는 기존 연동 파일과 같은 `admin_code, industry_code, base_month, actual_shops, estimated_shops`다. 지역·업종 코드는 문자열로 읽고 세 필드 `admin_code + industry_code + base_month`로 조회한다. 업종 이름은 검증표의 `industry_name`을 사용한다. 서비스 인허가 업종과 소진공 분류의 연결은 별도 매핑이 필요하다.

실제 점포 수와 ‘동네 여건으로 추정한 점포 수’를 표시한다. 추정치는 원래 정밀도로 저장하며 화면에서 정수로 반올림하고 ‘약’을 붙인다. 실제 점포 수 0은 0곳으로, 조회 행이 없으면 ‘이 기준월에는 비교 자료가 없어요’로 표시한다. 차이가 큰 곳에는 현장에서 유동인구와 경쟁 점포를 함께 확인하도록 안내한다.

시안의 업종 선택은 83개, 후보지는 152개 읍·면·동이다. 두 곳의 막대 눈금을 같게 맞추고 현재 눈금 상한을 안내한다. 같은 동네는 양쪽에 중복 선택할 수 없도록 했다. 가까운 동네 정보 사용 안내도 업종의 적용 방식에 따라 표시한다.

## 주민·상가 여건 함께 비교

추가 파일 `docs/a10/area_profiles_2026-09.csv`는 지역별 152행이다. `admin_code`로 점포 추정 표와 연결한다. `month`는 동일한 2026-09, `admin_area`는 지역명, `total`은 주민등록 거주자, `total_shops`는 전체 소진공 상가 수, `age_*`는 연령대별 주민 수다. 연령대 비중은 해당 주민 수를 `total`로 나눠 계산한다.

화면에는 주민 수, 선택한 관심 연령대의 주민 수·비중, 선택 업종을 뺀 다른 업종 점포 수를 나란히 표시한다. ‘다른 업종 점포 수’는 `total_shops - actual_shops`다. 연령 구성 전체 표에서도 두 후보지의 인원과 비중을 함께 표시한다. 주민 수와 상가 수는 예측치가 아닌 동일 기준월의 관측 집계다.

## 재현과 검증

`python scripts/evaluate_a10_expanded_improvements.py`로 83개 평가·선택을 재현하고 `python scripts/build_a10_expanded_preview.py`로 CSV와 두 후보지 시안을 생성한다. 조회 CSV 생성 후 시안만 갱신하려면 `python scripts/build_a10_area_comparison.py`를 실행한다. HTML 구조는 `scripts/a10_area_comparison_template.html`을 사용한다. 로컬에 기준월별 원본 상가 자료와 인구 자료가 필요하다. 2026-06 수집은 `scripts/collect_a10_202606.py`, 기존 2025-06·2026-09 출처는 [A08 문서](../a08/README.md)에 있다.

12,616개 조회 키와 원천 집계 일치, 업종별 152개 지역, 추정치 유한성·음수 없음, 개선 22개·기존 61개 방식을 대조한다. 시안에서는 83개 업종 × 3개 후보지인 249개 숫자 쌍이 CSV와 맞는지 확인한다. 실제 앱 연결과 운영 반영은 연동 담당자의 요청 범위에서 진행한다.

[검증 수치 JSON](expanded_validation_summary.json)에 세 시점의 방법별 평균·최대·구군별 오차와 원본 해시를 담았다. 브라우저에서 83개 선택 항목과 249개 CSV 숫자 쌍, 막대 범위, 모바일 가로 넘침 없음을 확인했다.

## 두 후보지 비교 확장 검증

2026-11-22 피드백을 반영해 고정된 세 동네 카드에서 사용자가 두 동네를 직접 선택하는 화면으로 바꿨다. 기본 선택은 카페·성내1동·범어3동·20대이며 선택에 따라 모든 카드와 연령 구성 표를 다시 계산한다.

브라우저에서 83개 업종 전환, 152개 서로 다른 지역 쌍, 11개 연령대 선택을 점검했다. 실제·추정 점포 수는 조회 CSV와, 주민 수·연령대 인원·비중·다른 업종 점포 수는 지역 집계 CSV와 대조했다. 같은 동네 중복 선택 방지, 점포 수 0, 조회값 누락 표시, 막대 범위와 모바일 가로 넘침 없음도 확인했다. 모델 추정치를 새로 학습한 단계는 아니며 기존에 검증한 83개 결과에 비교용 관측 자료를 연결한 화면 확장이다.
